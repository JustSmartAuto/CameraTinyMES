改善分析报告 · 交互原型

用真实产线数据生成客户向改善分析表：选日期 → 选小时 → 网页看图标注与写原因（草稿每 5 分钟存库） → 生成报告（先入库，再落盘 xlsx + pdf）→ 打开 xlsx 做发送前检查。改善措施落到工单闭环跟踪。

1
点击入口工具栏 / 菜单 / 托盘「生成改善报告…」
2
选日期与小时默认当日；可补做任一已生产日期；小时可勾选 0~23
3
打开工作台浏览器本地网页，URL 带 date/hours 参数
4
标注与撰写打 tag / 画框 / 写原因 / 关联工单；草稿自动存库
5
生成报告先入库（reports + report_files），再落盘 xlsx + pdf
6
发送前检查打开 xlsx 复核修改后再发客户；历史版本可重导出
WORKBENCH

改善分析报告工作台

三栏工作台：左侧工站相机、中间 NG 图片卡片、右侧原因分析与关联工单。生成前可先体验草稿自动保存。

  • 日期 + 小时参数栏，含「仅NG时段」快捷勾选
  • NG 图快速 tag：误判 / 产品自身NG / 外部原因（互斥）
  • 大图画框标注，写入草稿（真实环境写入 annotations）
  • 草稿每 5 分钟自动保存，可「加速演示 30×」观察倒计时
  • 生成进度 7 阶段：统计 → 取图 → 表格 → DISPIMG → PDF → 入库 → 落盘
  • 报告存档页：重新下载 / 删除 / 继续未完成草稿

TICKETS

工单管理

类 GitHub Issue：改善措施落成工单，责任、状态、期限与验证结果集中管理，可回链多份报告形成闭环。

  • 状态页签：开启中 / 处理中 / 已完成 / 已关闭 / 全部
  • 搜索 + 工站 / 类别 / 责任人 / 优先级过滤与排序
  • 详情抽屉：就地编辑改善措施、属性栏、时间线、评论
  • 状态机操作：开始处理 / 完成 / 关闭（必选原因）/ 重新打开
  • 关联报告双向链接，报告被清理时保留关联记录
  • 已完成工单在同站同类再次 NG 时标注「可能复发」
