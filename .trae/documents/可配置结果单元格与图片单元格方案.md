# 可配置「结果单元格 / 图片单元格 / 通过值」方案

## 背景

报告统计和网页工作台目前把 `C11`、`A0`、`OK`、`NG` 写死在代码里，而现场实际配置并不统一：

- `OP40-141` 没有 C11（A23 只是"正面/反面"，A6 是复合文本），结果在其他单元格；
- `OP40-142` 的判定结果是 `G24`（OK/NG）；
- `OP20-57` 的 C11 返回 `10`；
- 各相机图片单元格也可能不是 A0。

因此需要把「哪个单元格是判定结果、哪个单元格是报告图片、哪些文字算通过/不通过」做成按相机可配置的设置项。

## 设计决策

1. **设置项放在单元格上**（`CellConfig`），因为单元格本身就隶属于某台相机，且"配置单元格"对话框是现有唯一入口。
2. 新增字段：
   - `role`: `auto | data | result | image`，默认 `auto`；
   - `pass_values`: `list[str]`，默认空；
   - `fail_values`: `list[str]`，默认空。
3. **向后兼容推断**（`role=auto` 时）：
   - 结果单元格：名字规范化后为 `C11` 的单元格；没有则视为"未配置结果单元格"并告警。
   - 图片单元格：第一个 `data_type=image` 的单元格；没有再退回名字 `A0`。
   - 通过/不通过值：空列表时默认 `OK` / `NG`。
4. **每台相机最多一个结果单元格、一个图片单元格**：多个 `role=result` 取第一个并在统计告警中提示，避免 OP70 的 C39/C40/C41 子结果重复计数；`role=image` 时强制 `data_type=image`。
5. **判定优先级**（SQL）：`samples.ok` 非空优先；否则 `text` 去空格转大写后命中 `fail_values` 记为 NG、命中 `pass_values` 记为 OK、都不命中视为未判定。
6. **统计口径调整**：结果统计只计入"已判定"的记录。`OP20-57` 的 `10` 在配置 `pass_values=["10"]` 之前不计入总数，避免出现"总数 116、OK/NG 均为 0"的假数据。

## 分文件改动

### 1. config.py

- `CellConfig` 增加 `role`、`pass_values`、`fail_values` 三个字段及 `is_result_cell` / `is_image_cell` 属性。
- 新增模块级解析函数（单一真值，供 report/web/ui 共用）：
  - `result_cell(camera) -> CellConfig | None`
  - `image_cell(camera) -> CellConfig | None`
  - `result_tokens(cell) -> tuple[tuple[str, ...], tuple[str, ...]]`（去空格、转大写、去重）
  - `result_specs(cameras) -> list[(camera, cell, pass, fail)]`
- `load_config` 兼容旧 JSON（缺字段用默认值），校验 `role` 取值、把字符串 token 转 list。
- `save_config` 对默认值（`auto` / 空列表）不落盘，保证旧版程序读取新 `cameras.json` 时不会因未知字段报错。

### 2. storage.py

- 把全局 `_RESULT_STATUS` 改成 `_result_status(pass_tokens, fail_tokens) -> (expr_sql, args)`，保留 `ok` 优先；token 用 `?` 占位、`UPPER(TRIM(text)) IN (...)` 参数化，SQLite/MariaDB 通用。
- 新增 `range_result_summary(camera, cell, ranges, pass_tokens, fail_tokens)`：内层子查询算出 `status`，外层 `WHERE status IS NOT NULL` 后 `COUNT(*)` / `SUM(status=1)` / `SUM(status=0)`，返回列与原 `range_cell_summary` 一致。
- `range_ng_timestamps` / `range_ok_timestamps` 增加 token 关键字参数；参数顺序固定为 `(camera, cell) + token_args + range_args`。
- `range_cell_summary` 保留为默认 OK/NG 的兼容包装。
- 新增 `days_with_results_specs(cells, limit)`、`ng_hours_specs(day, specs)`：按相机/单元格循环查询后在 Python 端求并集，走 `camera+cell` 索引；旧 `days_with_results(cell="C11")`、`ng_hours(day, cell="C11")` 保留兼容。
- 注意 MariaDB 层只做 `? -> %s` 替换，SQL 里不能出现字面 `?`。

### 3. report.py

- `collect_stats`：删除全局 `RESULT_CELL` 依赖，逐相机取 `result_cell` 与 token，调用 `range_result_summary` / `range_ng_timestamps`；无结果单元格时告警"未配置结果单元格"。
- `build_daily_report`：OK 参考图、NG 抽图、嵌入图统一改用 `image_cell(camera)`，缺失时回退 A0。
- `_result_cell`、`auto_reason` 内的阈值/注解改为基于配置解析结果。
- `RESULT_CELL` / `IMAGE_CELL` 常量保留为默认兜底。

### 4. web.py

- 移除对 `RESULT_CELL` / `IMAGE_CELL` 的直接依赖，改用 `config` 的解析函数：
  - `_camera_note`：取该相机结果单元格的 `note`；
  - `/api/dates`：`days_with_results_specs(结果单元格集合)`；
  - `/api/summary`：`ng_hours_specs`；
  - `/api/station/*`：按相机结果单元格 + token 取 NG 时间与计数；
  - `frame_image`、`/api/image`、标注读写：按相机图片单元格。
- `ReportServer` 已持有 `self.cameras`，未知相机回退 A0。

### 5. ui.py

- `CellFormDialog`：新增「用途」下拉（自动/数据/结果/图像）、「通过值」「不通过值」输入（逗号分隔）；`role=image` 自动切 `data_type=image`，`role=result` 显示 token 输入并校验通过/不通过值不重叠。
- `CellEditorDialog`：表格增加「用途」「通过值」「不通过值」三列并加宽窗口。
- `ReportEntryDialog`：日期列表与「仅NG时段」改用 `days_with_results_specs` / `ng_hours_specs`（已有 `self._cameras`）。

### 6. images.py / worker.py

- `resolve_sources(..., with_render: bool = False)` 取代内部 `is_a0(cell_name)` 判断；`worker.py` 调用处传 `with_render = cell.name == image_cell(self.cfg).name`。
- 抓图条件补 `or cell.role == "image"`，保证只改 role 不改 data_type 的历史配置也能取图。

### 7. 文档

- 更新 `docs/当日改善报告功能设计.md` 中结果单元格/图片单元格/token 的说明；README 补充设置项说明。

## 兼容与风险

- 旧 `cameras.json` 不含新字段 → 默认 `auto`，推断仍为 C11/A0/OK/NG，行为不变。
- 新配置让旧版 exe 读取时可能因未知字段报错，`save_config` 省略默认值可规避。
- `OP40-141` 只能告警，不得用 A23 冒充结果；如确需统计 A6 复合文本，需要额外的包含/正则匹配模式（本次不做）。
- `OP20-57` 的 `10` 需现场确认语义后再配置，不能默认当 OK。
- 多结果单元格只取第一个并告警，不做子结果汇总。

## 验证（基于 192.168.10.64 / 2026-11-10）

1. **旧配置回归**（不配 role）：`collect_stats` 结果应与当前一致——OP20-58 total=861/ok=533/ng=328，OP10-25=148/72/76，OP20 total=118…（按现有聚合规则）。
2. **配置 G24 为结果单元格**（OP40-142）：统计出该相机 OK/NG，工站 OP40 不再为 0。
3. **配置 OP20-57**：`pass_values=["10"]` 后 total=116/ok=116/ng=0；不配置时该相机告警"无可判定记录"。
4. **OP40-141**：出现"未配置结果单元格"告警，报告脚注可见。
5. **图片单元格**：把某相机图片单元格改为非 A0（如 B0）后，网页缩略图/大图、报告嵌入图、标注接口均取新单元格。
6. **接口回归**：`/api/dates`、`/api/summary`、`/api/station/*`、`/api/image`、标注 GET/POST。
7. **持久化**：保存后重启，role/token 正确写回 `cameras.json`；再用纯旧 JSON 启动确认推断仍生效。
8. **打包**：`uv run python build_exe.py` 后启动 exe，重复第 6 步。

## 不在本次范围

- 复合文本包含/正则匹配；
- 单相机多个结果单元格的合并统计；
- 数据库 schema 变更（本需求不涉及表结构）。
