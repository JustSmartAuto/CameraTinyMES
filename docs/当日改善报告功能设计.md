# 「生成当日改善报告」功能设计

> 版本：v1.0　编写日期：2026-11-10
> 参考模板：`SAB视觉端NG原因分析_2611101713.xlsx`（客户向改善分析表）
> 关联模块：`ui.py`、`storage.py`、`videocodec.py`、`config.py`

---

## 1. 背景与目标

产线当前对客户输出改善材料时，由工程师手工从相机截图、清点数量、粘贴到 Excel，再逐张写原因分析，单条产线每天约需 1~2 小时，且数量统计依赖人工核对，易出错。

本功能在现有采集数据（工控机已全量落库）基础上，**一键生成与客户模板同构的 xlsx 改善分析表**：

- 自动填充：工站/相机信息、单站生产总数、NG 数量、NG 图片（最多 12 张/相机）、OK 参考图、NG 事实摘要；
- 人工补充：实物图片、原因分析结论、其他 NG 数量（系统无法自动判定，见 §4.3）；
- 输出为**客户向**文档：不含 IP、工控机路径、日志、内部变量名。

**触发方式**：用户手动点击，不做定时自动生成（避免无人值守时产出未审核的客户材料）。

## 2. 参考模板结构解析

### 2.1 版面（Sheet 名 = `9月19日`，即日期）

```
行1  B1: 项目名称：锦恒SAB项目 发货目的地：锦州        ← 合并整行
行2  B2: Line1                                        ← 产线名
行3  B3:J3  表头  No. | 工站&机台 | 相机型号&站名 | 实物图片 | OK相机图片 | 单站生产总数量 | NG数量总数 | 视觉NG数量 | 其他NG数量
     L3      "序号"（紧邻的 M3..X3 = 1..12，NG 图片编号）
行4-5   站 1：上行数据 + 下行「原因分析及改造解决方案」
行6-7   站 2
...
行44    B44: 已调完:20  台
行45    B45: 剩下:    台
```

**每个相机（站）固定占 2 行**：`start_row = 4 + 2 × (i-1)`。

- 上行：`L列 = "NG图片："`，`M..X = NG 图像`；
- 下行：`L列 = "原因分析及改造解决方案："`，`M..X = 对应图像的说明`（如"实际NG""视觉找线错误，添加分支…"）。

### 2.2 列定义与样式基线

| 列 | 字段 | 宽（字符） | 合并方式 | 来源 |
|---|---|---|---|---|
| B | No. | 7.58 | 每站纵向合并 2 行 | 自动序号 |
| C | 工站&机台 | 27.20 | **同工站(OP)所有相机纵向合并** | 配置/编号推断 |
| D | 相机型号&站名 | 44.41 | 每站 | `model` + 相机名 + 检测项 |
| E | 实物图片 | 41.17 | 每站 | **人工补充**（留空 + 浅灰提示） |
| F | OK相机图片 | 15.38 | 每站 | 自动取 1 张 OK 图 |
| G | 单站生产总数量 | 15.38 | **同工站合并** | C11 事件计数 |
| H | NG数量总数 | — | 同工站合并 | C11 `ok=0` 计数 |
| I | 视觉NG数量 | — | 同工站合并 | 默认 = H，人工可改 |
| J | 其他NG数量 | — | 同工站合并 | 默认 0，**人工补充** |
| K | 分隔 | 9.03 | — | 留空（绿色底贯穿） |
| L | 标签列 | 23.63 | — | 固定文案 |
| M..X | NG 图片 1~12 | 27.18 | — | 自动 |

样式基线（实测模板）：正文 `微软雅黑 12pt`，表头加粗 + 绿底 `#00B050`，水平/垂直居中、自动换行；行高：表头 18pt，数据行 77pt。

### 2.3 模板中不可自动化的部分（设计上必须显式保留给人）

1. **实物图片**（E 列）：产线实物拍照，系统无法获取；
2. **原因分析结论**（下行 M 列起的文字）：属于工程判断，系统只生成"事实摘要"供改写；
3. **其他 NG 数量**（J 列）：前工序/人工/设备导致的 NG，本系统只监听了本工位相机，无法归因。

> 结论：本功能定位是"**把重复劳动自动化 + 把判断留给人**"，而不是伪造分析结论。

## 3. 数据前提与口径

### 3.1 已具备的数据（无需改动采集端）

| 用途 | 数据源 | 说明 |
|---|---|---|
| 图像 | 单元格 `A0`（`data_type=image`，`event` 采样） | 原图存 `images` 表；已被后台压缩的存 `image_streams`（AV1） |
| OK/NG 判定 | 单元格 `C11`（`settable`，事件采样） | `samples.ok`：1=OK，0=NG，NULL=无判定 |
| 配方/换型 | `samples.job`、`images.job` | 当日可能多次切换 |
| 人工复核 | `annotations` | 已标注为"误判"的图，用于口径修正（可选） |
| 相机信息 | `config/cameras.json` | `name`、`cells[].note`、`model`/`station`（新增可选字段） |

### 3.2 时间窗口

- 默认：`当日 00:00:00.000` ~ `点击时刻`（同一工控机本地时区 Asia/Shanghai）；
- 可选：`昨日 08:00 ~ 今日 08:00`（夜班口径），由对话框选择；
- 边界使用 `[start, end)`，毫秒精度，与 `samples.ts` / `images.ts` 的字符串格式（`isoformat(timespec="milliseconds")`）一致，保证可走索引。

### 3.3 统计口径（关键设计决策）

同一工站（OP）常有 3~8 台相机同时拍同一批产品，**系统内无产品条码，无法跨相机对齐同一件产品**。因此：

| 指标 | 计算方式 | 理由 |
|---|---|---|
| 单站生产总数量 G | 取工站内各相机 `C11` 记录数的**中位数** | 事件丢帧只会少记不会多记，中位数抗个别相机掉线/重连重复 |
| NG数量总数 H | 取工站内各相机 NG 数的**最大值** | 同一产品可能被多台相机判 NG，求和会重复计数 |
| 视觉NG数量 I | 默认 = H（相机判 NG 即视为视觉判定结果） | 模板中"视觉NG"= 本工位视觉系统给出 NG 的产品数 |
| 其他NG数量 J | 默认 0，人工填写 | 前工序/人工 NG 不在本系统视野内 |

- 各相机单独计数写入报告底部「数据核对」区（第 2 个 Sheet），供工程师核对口径差异；
- 若工站内各相机计数偏差 > 5%，在「数据核对」区标黄提示，主表不做判断；
- 结算方式可在 `report.json` 中切换：`op_aggregate = median | max | first`（默认 `median`/`max`），便于不同产线适配。

> 口径在报告中以脚注明示，避免客户质疑数据来源：
> 「数量来自产线视觉系统逐件判定记录；同工站多相机按最大值去重合并。」

### 3.4 工站（OP）识别

1. 优先读 `cameras.json` 新增字段 `station`（如 `OP10`）与 `station_name`（如 `管壳合件组装`）；
2. 缺失时用相机名正则 `^(OP\d+)` 推断（`OP10-3` → `OP10`）；
3. 仍无法识别时，每台相机视为独立工站，`station` 留空，不合并单元格；
4. C 列显示格式：`OP10\n管壳合件组装`（与模板一致，换行）。

## 4. 功能设计

### 4.1 入口与交互

**入口（两处，同一函数）：**

1. 工具栏新增按钮：`生成当日改善报告`（位于「打开数据目录」右侧），点击后弹出参数对话框；
2. 「数据」菜单新增菜单项：`生成当日改善报告…`（与「导出」并列）。

按钮不常驻禁用；点击后在数据校验阶段给反馈（当日无数据时弹确认，见 §7）。

**参数对话框 `DailyReportDialog`（新建，复用主题样式）：**

| 项 | 控件 | 默认值 | 说明 |
|---|---|---|---|
| 报告日期 | 日期输入（`YYYY-MM-DD`）+ 昨天/今天快捷按钮 | 今天 | 决定 sheet 名与查询窗口 |
| 统计时段 | 下拉：`自然日 00:00-现在` / `夜班 08:00-08:00` | 自然日 | 夜班跨日时窗口顺延 |
| 项目名称 | 单行文本 | `settings.json` 的 `project_name` | 写入 B1 |
| 发货目的地 | 单行文本 | `settings.json` 的 `destination` | 写入 B1 |
| 产线名 | 单行文本 | `Line1` | 写入 B2 |
| 包含相机 | 复选列表（默认全选，支持按工站全选/反选） | 全部启用相机 | 支持只出某几个工站 |
| 每站 NG 图片上限 | 数字（1~12） | 6 | 控制文件体积 |
| 生成 OK 参考图 | 复选框 | 勾选 | 关闭可显著减小文件 |
| 图片长边像素 | 下拉：640 / 800 / 1024 | 800 | 客户看细节就选大 |
| 输出目录 | 只读文本 + 「打开」按钮 | `{data_dir}/reports/` | — |

按钮：`生成` / `取消`。点击「生成」后对话框按钮置灰，进度区替换为进度条。

**进度与结果：**

- 复用并泛化现有 `ExportProgressDialog`（`ui.py#L1555`）：新增 `title` / `desc` / `on_cancel` 参数，文案改为「采集数据 → 提取图像 → 写入表格 → 保存」四阶段；
- 完成：提示「报告已生成」+「打开文件」+「打开所在目录」+「关闭」；
- 取消：立即置位 `threading.Event`，删除临时文件，提示「已取消，未生成文件」；
- 失败：展示错误摘要（数据库不可用 / 磁盘满 / 无有效图像），保留日志到 `logs/`。

### 4.2 处理流程

```
点击 → 参数校验 → 后台线程 build_daily_report()
  ├─ 1. 聚合统计：按工站取 C11 计数/NG 数 / job 列表
  ├─ 2. 选取图像：NG 时间戳 → 匹配 A0 图像 → 均匀抽样 → 缩略
  ├─ 3. 生成工作簿：表头 → 逐站写行 → 合并 → 样式 → 插图
  ├─ 4. 写「数据核对」Sheet
  └─ 5. 保存 → 回调 UI
```

### 4.3 图像选取算法（核心）

**NG 图（M..X 列，每站 ≤ 上限）**

1. 取该相机当日 `C11` 中 `ok=0` 的记录，得到 NG 时间戳集合 `T_ng`（升序）；
2. 对每个 `t ∈ T_ng`，在该相机 `A0` 图像中找 `|ts - t|` 最小且 `≤ 5s` 的一帧，作为该次 NG 的证据图；同一帧只使用一次（按 `ts` 去重）；
3. 若 `|T_ng| > 上限`：按时间轴把 `T_ng` **等距分段**，每段取最早的 1 张，保证覆盖全天而非集中在某一时段；
4. 读取图像统一走 `videocodec.load_images(storage, camera, "A0", start=day_start, end=day_end)`——该函数同时合并 `images` 原图与 `image_streams` AV1 分片解码结果，**不可直接查 `images` 表**（全库已被后台压缩，直接查会取不到图）；
5. 缩略：等比缩放至长边 ≤ 设定值，转 JPEG(q=85)，单张目标 < 120KB；
6. 长宽比异常（宽高比 > 8 或 < 1/8）的图判为无效，跳过并记录。

**OK 参考图（F 列，每站 1 张）**

- 取当日 `ok=1` 的记录，取时间中位数附近最近一张 `A0`；无 OK 记录则不填（保持模板的"部分站留空"现状）。

**图片说明行**

- 默认写 `实际NG`；
- 若该帧在 `annotations` 中已被标注为误判，写 `复核：误判（{标注人}）`，并同步把 HN 计入「其他NG」建议值（只提示，不自动改主表）。

### 4.4 原因分析草案（自动，可被人工覆盖）

下行 `M{r+1}` 写入事实摘要，工程师在 Excel 中直接改写为对外结论。模板：

```
视觉NG {n} 件（不良率 {p:.1f}%）；检测项：{notes}；判定阈值：{lower}~{upper}；
NG 时段：{first_time}~{last_time}；配方：{jobs}；{连续NG提示}
```

- `{notes}` 取 `cameras.json` 中该相机 C11（或主判定单元格）的 `note`；
- `{连续NG提示}`：若存在连续 ≥ 3 件 NG，追加「{time} 起连续 {k} 件 NG，疑似工装/来料异常」；
- 全部为**事实陈述**，不含因果结论，避免把系统推测当成客户结论；
- 若当日该站 NG = 0，写 `当日无 NG，维持现状`。

### 4.5 底部汇总

| 单元格 | 内容 |
|---|---|
| `B{last+1}` | `已调完:{n} 台`，n = 当日有 OK 记录的相机数 |
| `B{last+2}` | `剩下:{m} 台`，m = 配置启用但当日无记录的相机数 |
| `B{last+3}` | `合计：生产 {N} 件，NG {H} 件（{p:.1f}%）` |
| `B{last+4}` | 脚注（灰色 9pt）：统计口径说明 + 生成时间 + 数据库类型（SQLite/MariaDB） |

## 5. 输出规范

- 文件名：`{项目名称}视觉端NG原因分析_{YYYYMMDDHHmm}.xlsx`（项目名去除空格与非法字符）；
- 保存位置：`{data_dir}/reports/`（不存在则创建）；
- Sheet 1：`{M月D日}`（与模板一致，如 `9月19日`）；
- Sheet 2：`数据核对`（内部用，交付客户前可删除）——列：相机、工站、C11 记录数、OK、NG、首/末记录时间、当日配方、图源（原图/AV1）、缺失图数；
- 打印设置：A3 横向、缩放到 1 页宽、冻结 `B4`、表头重复打印；
- **脱敏**：不写相机 IP、端口、工控机路径、数据库连接串、日志内容、内部单元格地址（`A0`/`C11` 一律显示为「图像」「判定结果」）。

**关于图片嵌入方式（必须知悉的限制）**

- 参考模板使用 WPS 专有 `DISPIMG` 公式（"嵌入单元格"），openpyxl 无法写出该公式，写出的普通图片在 WPS/Excel 中均可正常显示，但属于"浮动图片"而非"嵌入单元格"；
- 若客户强制要求嵌入单元格效果，交付说明中注明「用 WPS 打开 → 图片上右键 → 嵌入单元格」；不为此引入 xlsx 底层 XML 私有扩展（维护成本高、跨版本易坏）。

## 6. 技术方案

### 6.1 新增文件

```
src/cameratinymes/report.py        # 报告生成（纯后端，无 tkinter 依赖）
src/cameratinymes/report.json 默认配置由 data_dir/config/report.json 覆盖
```

### 6.2 主要接口

```python
# report.py
@dataclass
class ReportOptions:
    day: date
    title_project: str
    destination: str
    line_name: str = "Line1"
    shift: str = "day"            # day=00:00-现在, night=08:00-次日08:00
    cameras: list[str] | None = None   # None=全部
    ng_images_per_station: int = 6
    include_ok_image: bool = True
    image_max_edge: int = 800
    station_of: Callable[[str], str] | None = None   # 相机名→工站（默认正则）

@dataclass
class DailyReportResult:
    path: Path
    stations: int
    products: int
    ng: int
    skipped_images: int
    warnings: list[str]

def build_daily_report(
    storage, camera_cfgs, options: ReportOptions, out_dir: Path,
    progress_callback=None,      # callable(phase:str, done:int, total:int, message:str)
    cancelled: threading.Event | None = None,
) -> DailyReportResult
```

- 生成函数不依赖 `tkinter`，可被脚本/测试直接调用；
- 复用 `storage.export_xlsx` 中的取消检查点惯例：每 500 行、每 20 张图 `_check()`。

### 6.3 数据访问

**新增 `storage.py` 聚合方法**（避免把全天 `samples` 全量拉进内存）：

```python
def daily_cell_summary(self, day_start, day_end) -> list[tuple]:
    """[(camera, cell, total, ok_cnt, ng_cnt, first_ts, last_ts)]
    仅取 cell IN ('C11') 的聚合，走 idx_samples_cam_job 索引。"""

def daily_ng_timestamps(self, camera, cell, day_start, day_end) -> list[str]:
    """当日 NG 时间戳（升序），用于图像匹配。"""

def daily_jobs(self, camera, day_start, day_end) -> list[tuple[str|None, int]]:
    """当日配方及记录数。"""
```

SQL 示例（MariaDB 由 `_sql()` 自动把 `?` 转 `%s`）：

```sql
SELECT camera, cell, COUNT(*) AS total,
       SUM(CASE WHEN ok=1 THEN 1 ELSE 0 END) AS ok_cnt,
       SUM(CASE WHEN ok=0 THEN 1 ELSE 0 END) AS ng_cnt,
       MIN(ts), MAX(ts)
FROM samples
WHERE cell=? AND ts>=? AND ts<?
GROUP BY camera, cell
```

**图像读取**：`videocodec.load_images(...)`（内部已做 AV1 分片解码 + 缓存 + 按 stream 及时释放）；若 `videocodec.available()` 为 False（无 ffmpeg）则只回退查 `images` 表，并在报告脚注标注「部分历史图像已被压缩，本次未包含」。

| 位置 | 改动 |

线程安全约束（沿用现有约定）：

- 生成在后台线程执行，**不得**在后台线程操作任何 tkinter 控件；
- 进度、完成、失败统一通过 `queue.Queue` + 主线程 `after(100, ...)` 轮询；
- 生成期间禁用入口按钮，防止并发写同名文件（文件名已带分钟级时间戳，仍做按钮级互斥）。

### 6.5 性能与资源

| 场景 | 预估 |
|---|---|
| 30 台相机 / 全天 8000 条判定 / 每站 6 张 NG 图 | 查询 < 1s；AV1 解码约 1.5s/分片，命中缓存的同分片只解一次；总耗时 15~30s |
| 报告体积 | 每张图 ~100KB × 180 张 ≈ 18MB；关掉 OK 图或降上限可压到 8MB 内 |
| 内存 | 图像逐张读、写入后立即释放，峰值 ≈ 单张解码结果 + Workbook；禁止一次性 `load_images` 全站全量 |

优化点：按「相机 + 时间窗」分批取图；同一 AV1 分片在同一批次内只解码一次（`load_images` 已实现 cache）。

## 7. 边界与异常

| 场景 | 处理 |
|---|---|
| 当日无任何 `C11` 记录 | 弹确认「当日无生产数据，是否仍生成空表模板？」→ 是则生成仅含表头/工站列表的模板 |
| 某相机当日无 A0 图像（相机未连/停用） | 该站数量正常填，图片区写「当日无图像」，`数据核对` 中记 `缺失图数` |
| `images` 与 `image_streams` 均无数据 | 跳过图片，继续生成，告警计入 `warnings` |
| ffmpeg 缺失 | 只用原图；报告中脚注说明；不阻止生成 |
| 数据库在生成中断开 | 捕获异常 → 提示「数据库连接异常，请检查后重试」，删除临时文件，不产出半成品 |
| 磁盘空间不足 | 保存异常捕获 → 提示目标目录不可写；临时文件清理 |
| 用户中途取消 | `cancelled.set()`；每 20 张图/500 行检查一次；退出时删除临时文件 |
| 重复点击 | 按钮置灰 + 生成中标志位 |
| 相机名不含 OP 编号 | 不合并工站单元格，按独立站展示 |
| `C11` 当日大量 NULL（无判定） | 只统计 `ok IS NOT NULL` 的记录，并在脚注给出「无判定 {k} 条，未计入」 |

## 8. 验收标准

1. 数据准确性：任选一天，报告 G/H/I 列与「数据核对」Sheet 的逐相机计数可复核一致；H 与 I 相等，J 为 0（未人工填写时）。
2. 图像可用性：每站 NG 图数量 ≤ 上限，且全部来自当日 `ok=0` 时刻 ±5s 内；被 AV1 压缩过的历史图也能正常显示（关键回归点）。
3. 版面对齐：行高/列宽/表头绿底/2 行 1 站/工站纵向合并/底部「已调完/剩下」与参考模板一致。
4. 交互：点击→参数→进度条→完成可打开文件；全程主界面不卡顿；取消后无残留文件。
5. 脱敏：文件中搜索不到 IP、`D:/JustSmart`、`A0`、`C11`、日志文本。
6. 兼容：SQLite 与 MariaDB 两种后端生成结果一致；旧版 `cameras.json`（无 `station`/`model` 字段）可直接使用。
7. 性能：30 台相机、单站 6 张 NG 图的典型工况下，生成耗时 ≤ 60s，文件 ≤ 30MB。

## 9. 非目标

- 不做自动缺陷分类/自动归因（不猜测"找线错误"这类结论）；
- 不做 PDF/PPT 输出（需要时另立需求）；
- 不接入客户 MES 的产品序列号对齐（跨相机产品关联留待有扫码数据后再做）；
- 不替代现有「导出xlsx」（后者是工程师用的全量数据明细，本功能是客户向汇总材料）。
