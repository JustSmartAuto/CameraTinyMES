# 「生成改善分析报告」功能设计（支持任意已生产日期）

> 版本：v1.9　编写日期：2026-11-10
> 参考模板：`SAB视觉端NG原因分析_2611101713.xlsx`（客户向改善分析表）
> 关联模块：`ui.py`、`web.py`、`report.py`、`wpsdispimg.py`、`pdfrender.py`、`storage.py`、`videocodec.py`、`config.py`

---

## 1. 背景与目标

产线当前对客户输出改善材料时，由工程师手工从相机截图、清点数量、粘贴到 Excel，再逐张写原因分析，单条产线每天约需 1~2 小时，且数量统计依赖人工核对，易出错。

本功能在现有采集数据（工控机已全量落库）基础上，提供**本地 Web 工作台 + 一键生成与客户模板同构的 xlsx 改善分析表**：

- 桌面端入口：先选日期（默认当日，可选任一已生产日期）+ 勾选小时，确认后打开浏览器；
- 网页里：逐站浏览 NG 渲染图（含检测图形叠加）、画框标注误判、撰写原因分析（草稿每 5 分钟自动存数据库）；
- 自动填充：工站/相机信息、单站生产总数、NG 数量、NG 图片（最多 12 张/相机）、OK 参考图、NG 事实摘要；
- 图片以 **WPS「嵌入单元格」（`DISPIMG`）** 方式写入，随单元格缩放/排序，不浮动错位；
- 人工补充：原因分析结论、其他 NG 数量（由网页快速 tag 自动汇总，见 §4.2）；实物图片为**可选**列，默认隐藏；
- 网页快速 tag：每张 NG 图一键标记 `误判` / `产品自身NG` / `外部原因`，直接决定「视觉NG / 其他NG」口径；
- **改善措施关联工单**：原因分析中的改造方案落到工单（类 GitHub Issue），工单可回链多次报告，形成"发现问题 → 派工 → 验证 → 关闭"的闭环（§4.8）。
- **报告存档**：每次生成先完整写入数据库（元数据 + xlsx/pdf 二进制），再从库中落盘为 `视觉改善分析报告_{时间戳}.xlsx` 与 `.pdf`，历史版本可随时重新导出；
- **PDF 交付版**：按 xlsx 表结构渲染为 A3 横版单页、米黄色纸张底，适合直接打印/发客户；
- **支持任意已生产日期**：入口先选日期（默认当日）+ 选小时，再进入网页编写；历史日期可补做/重做报告；
- 输出为**客户向**文档：不含 IP、工控机路径、日志、内部变量名。

**触发方式与总体流程**（用户手动，不做定时自动生成）：

```
点击「生成改善报告…」
  → ① 选择日期（默认当日，可选任一已生产日期，不允许未来日期）
  → ② 勾选小时（默认 0 点 ~ 当前小时；历史日期 24 小时全可选）
  → ③ 确认 → 浏览器打开工作台（URL 带 date / hours 参数）
  → ④ 网页内：看图打 tag / 画框标注 / 写原因 / 关联工单（草稿每 5 分钟自动存数据库）
  → ⑤ 点击「生成报告」→ 先入库 → 再落盘 xlsx + pdf
  → ⑥ 打开 xlsx 做发送前检查与修改
```

## 2. 参考模板结构解析

### 2.1 版面（Sheet 名 = `9月19日`，即日期）

```
生成时间
行3  B3:J3  表头  No. | 工站&机台 | 相机型号&站名 | 实物图片 | OK相机图片 | 单站生产总数量 | NG数量总数 | 视觉NG数量 | 其他NG数量
     L3      "序号"（紧邻的 M3..X3 = 1..12，NG 图片编号）
行4-5   站 1：上行数据 + 下行「原因分析及改造解决方案」
行6-7   站 2
...
```

**每个相机（站）固定占 2 行**：`start_row = 4 + 2 × (i-1)`。

- 上行：`L列 = "NG图片："`，`M..X = NG 图像`；
- 下行：`L列 = "原因分析及改造解决方案："`，`M..X = 对应图像的说明`（如"实际NG""视觉找线错误，添加分支…"）。

### 2.2 列定义与样式基线

| 列 | 字段 | 宽（字符） | 合并方式 | 来源 |
|---|---|---|---|---|
| B | No. | 7.58 | 每站纵向合并 2 行 | 自动序号 |
| C | 工站&机台 | 27.20 | **同工站(OP)所有相机纵向合并** | 配置/编号推断 |
| D | 相机型号&站名 | 44.41 | 每站 | `model` + 相机名 + 检测项 |
| E | 实物图片（可选） | 41.17 | 每站 | **默认隐藏列**；页面开启后保留空白单元格待人工补图 |
| F | OK相机图片 | 15.38 | 每站 | **默认隐藏列**；页面开启后自动取 1 张 OK 图 |
| G | 单站生产总数量 | 15.38 | **同工站合并** | C11 事件计数 |
| H | NG数量总数 | — | 同工站合并 | C11 `ok=0` 计数 |
| I | 视觉NG数量 | — | 同工站合并 | 默认 = H，人工可改 |
| J | 其他NG数量 | — | 同工站合并 | 默认 0，**人工补充** |
| K | 分隔 | 9.03 | — | 留空（绿色底贯穿） |
| L | 标签列 | 23.63 | — | 固定文案 |
| M..X | NG 图片 1~12 | 27.18 | — | 自动 |

样式基线（实测模板）：正文 `微软雅黑 12pt`，表头加粗 + 绿底 `#00B050`，水平/垂直居中、自动换行；行高：表头 18pt，数据行 77pt。

### 2.3 模板中不可自动化的部分（设计上必须显式保留给人）

1. **实物图片**（E 列）：**非必须项，默认隐藏整列**（`column_dimensions["E"].hidden = True`），PDF 也不绘制该列；页面顶栏开关「显示实物图片列」打开后，该列保留 + 浅灰提示文字，供在 WPS 中拖入照片（落位后仍是嵌入单元格）。开启该列时 PDF 同步显示空列，便于打印后手写贴图；
2. **原因分析结论**（下行 M 列起的文字）：属于工程判断，系统只生成"事实摘要"作为初稿，最终结论在 Web 工作台里撰写/确认；
3. **其他 NG 数量**（J 列）：前工序/人工/设备导致的 NG，本系统无法自动归因；通过网页快速 tag（`误判` / `外部原因`）自动汇总，**页面可直接改数**（人工改数优先，并在报告中注明「人工调整」）。

> 结论：本功能定位是"**把重复劳动自动化 + 把判断留给人**"，而不是伪造分析结论。

## 3. 数据前提与口径

### 3.1 已具备的数据（无需改动采集端）

| 用途 | 数据源 | 说明 |
|---|---|---|
| 图像 | 单元格 `A0`（`data_type=image`，`event` 采样） | 原图存 `images` 表；已被后台压缩的存 `image_streams`（AV1） |
| OK/NG 判定 | 单元格 `C11`（`settable`，事件采样） | `samples.ok`：1=OK，0=NG，NULL=无判定 |
| 配方/换型 | `samples.job`、`images.job` | 当日可能多次切换 |
| 人工复核 | `annotations` | 已标注为"误判"的图，用于口径修正（可选） |
| 相机信息 | `config/cameras.json` | `name`、`cells[].note`、`model`/`station`（新增可选字段） |

### 3.2 日期与时间窗口：先选日期，再按小时勾选

**日期**：默认**当日**，可选任意「已生产日期」（存在 `samples` 记录的日期）；不允许选未来日期。日期在桌面端入口对话框里选（§4.1），也可在页面顶栏点「重新选择」回到同一对话框。历史日期用于补做漏报、客户追溯、复盘。

- 日期上限 = 今天；下限 = 数据库最早一条 `C11` 记录所在日期（无数据日期直接置灰）；
- 切换日期后重新拉取工站列表、NG 数与图片，并自动读取该日草稿（§4.2 草稿与恢复）。

统计粒度到小时，页面提供 **0~23 共 24 个勾选框**（小时条）：

- **默认勾选 `0` 点到「当前小时」**（如今天 17:32 触发 → 勾选 `0..17`）；选历史日期时默认 `0..23` 全选；
- 未来小时置灰不可勾（仅当天有未来小时；历史日期 24 小时全部可选）；
- 快捷操作：`全选` / `0点-当前小时` / `清空` / `仅NG时段`（自动勾选存在 NG 的小时）；
- 勾选为空时不允许生成，页面上「生成」按钮置灰并提示；
- 夜班口径不再单独建模：勾选 `20..23 + 0..7` 即可表达，避免两套时间语义。

**查询实现**：把勾选的小时合并成连续段，转成 `[start, end)` 半开区间：

```
选中 [8,9,10, 14] → 段 [(08:00, 11:00), (14:00, 15:00)]
SQL: ... AND ((ts>=? AND ts<?) OR (ts>=? AND ts<?))
```

- 时间戳与 `samples.ts` / `images.ts` 一致使用 `isoformat(timespec="milliseconds")`，段边界为整点，可走 `idx_samples_cam_job(camera, job, ts)` 索引；
- 报告脚注写明「统计时段：08:00-11:00、14:00-15:00（共 4 小时）」，避免客户误读为全天；
- 小时口径同时作用于：数量统计、NG 图片抽取、OK 参考图选择、原因分析摘要中的「NG 时段」。

### 3.3 统计口径（关键设计决策）

同一工站（OP）常有 3~8 台相机同时拍同一批产品，**系统内无产品条码，无法跨相机对齐同一件产品**。因此：

| 指标 | 计算方式 | 理由 |
|---|---|---|
| 单站生产总数量 G | 取工站内各相机 `C11` 记录数的**中位数** | 事件丢帧只会少记不会多记，中位数抗个别相机掉线/重连重复 |
| NG数量总数 H | 取工站内各相机 NG 数的**最大值** | 同一产品可能被多台相机判 NG，求和会重复计数 |
| 视觉NG数量 I | `I = H - M - X`（`M`=误判 tag 数，`X`=外部原因 tag 数） | 真实由视觉判定的 NG；未打 tag 的 NG 默认按视觉NG计（保守口径） |
| 其他NG数量 J | `J = M + X`（快速 tag 自动汇总，页面可手工覆盖） | 误判与外部原因不属于本工位视觉问题，但客户口径里都算"其他NG" |

其中 `M` / `X` 只统计**本工站范围内、已打 tag 的 NG 事件**：

- tag 记录在 `report_tags`（按 `ts` 关联，不依赖 `images.id`，**不阻塞 AV1 压缩**）；
- 若页面手工改了 J，则以其为准，同时 `I = H - J`（保持 `I + J = H` 恒等），并在脚注注明「其他NG含人工调整」；
- 「数据核对」Sheet 额外列出 `误判 / 产品自身NG / 外部原因 / 未标注` 四项计数，便于复核；
- tag 数超过 H（异常，如重复打标）时按 H 截断并告警，绝不出现 `I < 0`；
- 各相机单独计数写入报告底部「数据核对」区（第 2 个 Sheet），供工程师核对口径差异；
- 若工站内各相机计数偏差 > 5%，在「数据核对」区标黄提示，主表不做判断；
- 结算方式可在 `report.json` 中切换：`op_aggregate = median | max | first`（默认 `median`/`max`），便于不同产线适配。

> 口径在报告中以脚注明示，避免客户质疑数据来源：
> 「数量来自产线视觉系统逐件判定记录；同工站多相机按最大值去重合并。」

### 3.4 工站（OP）识别

1. 优先读 `cameras.json` 新增字段 `station`（如 `OP10`）与 `station_name`（如 `管壳合件组装`）；
2. 缺失时用相机名正则 `^(OP\d+)` 推断（`OP10-3` → `OP10`）；
3. 仍无法识别时，每台相机视为独立工站，`station` 留空，不合并单元格；
4. C 列显示格式：`OP10\n管壳合件组装`（与模板一致，换行）。

## 4. 功能设计

### 4.1 载体形态：内嵌 Web 工作台（高端口）

沿用 README 中「tkinter + 内嵌 Web」的既有形态（`reference/相机数据监控器_web_2610171547.py`）：**tkinter 只负责主界面、托盘与入口，改善报告的全部编辑工作（勾时段、看 NG 图、画框标注、写原因、生成）在一个本地 Web 单页里完成**。原因：

- 图片浏览/缩放/画框在 Web 端（`<canvas>`）体验远好于 tkinter 手绘；
- 报告是"逐站看图 + 写文字"的连续工作流，Web 布局可一屏完成，不必反复开关对话框；
- 页面无外部依赖（不引 CDN、不用框架），产线离线可用，与"轻量单机"定位一致。

**服务宿主**

| 项 | 设计 |
|---|---|
| 实现 | 标准库 `http.server.ThreadingHTTPServer` + `socketserver`，不新增三方依赖 |
| 监听 | `0.0.0.0`（**允许局域网其他工控机访问**，见下方「局域网访问与安全」）；可通过 `settings.json` 的 `web_host` 改回 `127.0.0.1` 仅本机模式 |
| 端口 | 默认 `18110`；被占用则 `+1` 顺延（最多 20 次），最终端口写回 `config/settings.json` 的 `web_port` |
| 生命周期 | 随主程序启动（`web.py` 守护线程），随托盘「退出」关闭；`daemon_threads=True` |
| 静态资源 | `src/cameratinymes/webui/`（`index.html` / `app.js` / `style.css`），PyInstaller 打包时 `--add-data`，并用 `_MEIPASS` 兼容（同现有 `assets/` 取法） |
| 打开方式 | 入口对话框确认后 `webbrowser.open(f"http://127.0.0.1:{port}/report?date={d}&hours={h}")`（本机用回环地址）；其他工控机访问 `http://{本机局域网 IP}:{port}/report?date={d}&hours={h}`；已打开则不重复开窗（前端 `localStorage` 记住上次日期/小时） |

**局域网访问与安全**

监听 `0.0.0.0` 后，同网段任意机器都能打开工作台，需配套以下设计：

| 项 | 设计 |
|---|---|
| 地址发现 | 启动时用 `socket` UDP connect 默认路由取本机局域网 IP（失败回退 `gethostbyname`，过滤 `169.254.*` 与虚拟网卡），拼出 `http://{ip}:{port}/report?...` |
| 地址展示 | 入口对话框底部显示两行地址：`本机  http://127.0.0.1:18110/...`、`局域网 http://192.168.x.x:18110/...` + `复制局域网地址` 按钮；主窗口状态栏与托盘提示同步显示；端口写入 `reports/.web_port` |
| 防火墙 | 首次以 `0.0.0.0` 监听时 Windows 会弹「允许访问」；文档与页面提示需放行**专用网络**该端口。若检测到连接被拒，状态栏提示「可能被防火墙拦截」并给出放行命令说明（`netsh advfirewall firewall add rule ...`，需管理员，不自动执行） |
| 本机/远程权限 | 写接口（生成、草稿、标注、tag、工单）本机与局域网均可调用；**敏感操作只允许回环地址**：`POST /api/open_entry`、`/api/reports/{id}/export` 的「打开所在目录」、删除存档、退出程序、`os.startfile` 相关接口，远程调用返回 403 |
| Origin 校验 | POST 允许 `http://127.0.0.1:{port}`、`http://localhost:{port}`、`http://{本机IP}:{port}`；**空 Origin（脚本/curl）默认拒绝**，除非携带 `X-CTM-Token` |
| 可选访问口令 | `settings.json` 的 `web_token`（默认空 = 关闭）；设置后所有页面/接口需 `?k={token}`，校验通过写 Cookie 记住；用于车间网络存在无关人员时的最低限度防护 |
| 审计 | 启动、生成、落盘、删除、登录失败均记录客户端 IP 到日志，便于追溯误操作来源 |
| 并发编辑 | 多客户端可同时打开同一天页面；草稿保存带 `updated_at` 做乐观锁，冲突时提示「他人已更新，是否覆盖」，默认保留服务端较新版本（见 §4.2 草稿） |

> 定位说明：这是产线内网工具，默认信任专用网络、不做账号体系；口令与 IP 白名单是最小防护，不替代企业网络隔离。

**入口（两处，同一函数 `MonitorApp.open_report_workbench()`）**

1. 工具栏新增按钮：`改善报告`（位于「打开数据目录」右侧）；
2. 「数据」菜单新增菜单项：`生成改善报告…`；
3. 托盘菜单新增：`改善报告工作台`（与「显示/隐藏主窗口」并列）。

点击后先弹出 **tkinter 入口对话框**（`ReportEntryDialog`），确认后才打开浏览器：

```
┌─ 生成改善分析报告 ──────────────────────────┐
│ 统计日期  [2026-11-10 ▾]  ← 默认当日，可选已生产日期 │
│ 统计时段  0 1 2 ... 17 18 ... 23（复选框，未来小时置灰）│
│           [全选] [0点-当前小时] [清空] [仅NG时段]      │
│ 提示：当日已勾选 18 小时，预计 12 个工站              │
│ 访问地址  本机   http://127.0.0.1:18110/report?...    │
│           局域网 http://192.168.1.23:18110/report?...│
│           [复制局域网地址]（其他工控机可直接打开）    │
│                              [取消] [打开工作台]      │
└────────────────────────────────────────────┘
```

- 日期下拉只列有 `C11` 记录的日期（倒序），默认选中当日；
- 小时默认 `0..当前小时`；选历史日期时默认全选、无置灰；
- `打开工作台` = 记住本次日期/小时 → `webbrowser.open(url)` → 页面按 URL 参数初始化并自动载入草稿；
- 页面顶栏可点「重新选择」→ 调 `POST /api/open_entry` 让桌面端再弹同一对话框（桌面主窗口若已最小化到托盘则先显示），避免网页里重复实现日期控件。

### 4.2 页面结构与交互

单页三段式布局（宽度 < 1100px 时右栏折到下方）：

```
┌──────────────────────────────────────────────────────────────────────┐
│ 顶栏：日期[2026-11-10 ▾重新选择] 小时条[0..23 复选] 快捷[全选|0-当前|清空|仅NG]│
```

**左栏（工站列表）**

- 按 `station`（OP）分组，组头显示该 OP 的相机数与 NG 合计；
- 每行：相机名 + 检测项 note + NG 数徽标（0 显示灰色「0」）+ 状态点（有 NG 红点 / 已写原因绿点 / 未填灰点）；
- 点击切换中栏，键盘 ↑/↓ 可连续切换。

**中栏（NG 图片卡片）**

- 卡片：缩略图（服务端取该帧**渲染图**缩到 320px 返回）、时间戳（HH:MM:SS）、判定标记、tag 色条；
- 图片口径：缩略图与大图**均来自相机渲染图**（图像 + 检测图形叠加，`kind=render`），不使用相机原图（`kind=image`）；该帧无渲染图（老数据未生成 / 渲染失败）时回退原图，卡片角标显示「原图」；
- 标注坐标系：`<canvas>` 覆盖层与图片同源，框坐标基于**渲染图像素坐标**，与报告嵌入图是同一张、同一像素尺寸，保证「所见即所得」；
- **快速 tag（一级交互，无需打开大图）**：卡片底部三个 chip 按钮——`误判`（灰）/ `产品自身NG`（红）/ `外部原因`（蓝）：
  - 单击即保存（`POST /api/tag`），再点已选 chip 取消；三者**互斥单选**；
  - 键盘 `1/2/3` 对当前聚焦卡片打标，`0` 清除，连续浏览时手不离键盘；
  - 卡片左上角显示对应颜色圆点，未打标为空心灰圈；
  - 打标后该站左栏状态点变蓝（有 tag 未写原因）/ 绿（原因已写）；
- 点击缩略图 → 大图弹层：渲染图 + `<canvas>` 覆盖层，鼠标拖拽画矩形（可多框、可删除），每框填写 `label` 与 `description`（误判原因/注意点）；顶部同样有三个 tag chip；
- 「保存标注」→ 写框到 `annotations` 表（XAnyLabeling 3.3.x，`shapes[].shape_type="rectangle"` + `imageData` 内嵌 Base64，**不使用 imagePath**），`reviewer` 取页面设置的操作人（默认 `产线工程师`）；
- 快速 tag 与画框**互不依赖**：只打 tag 不画框也能生成报告；画框不选 tag 时按「未标注」处理（计入视觉NG）；
- 报告下行写 `复核：{tag}（{reviewer}）`，无 tag 写 `实际NG`；
- 每站只展示 ≤ 上限（默认 6，可改 1~12）张，顺序与报告中 M..X 列一致 —— **页面选中的图即报告里的图，所见即所得**，避免生成后还要在 Excel 里换图。

**右栏（原因分析）**

- 首次进入自动填 §4.5 的事实摘要（只读事实，不含结论）；
- `textarea` 可自由改写；`恢复自动摘要` 一键还原；`保存` 写入草稿；
- 失焦/停止输入 2s 自动保存（防抖），标题栏显示「已保存 18:32:05」。

**底部（进度）与后台任务**

- **生成与落盘全部在后台任务中执行**：`POST /api/report/generate` 立即返回 `task_id`（202），HTTP 线程不承担任何计算/IO 循环，页面不阻塞、可继续看图写原因；
- 页面轮询 `GET /api/tasks?active=1`（500ms）刷新任务进度，展示 `阶段 + 已完成/总数 + 当前动作`；阶段含「生成表格 → 渲染 PDF → 存档入库 → 落盘 xlsx → 落盘 pdf」，**落盘阶段按分块字节进度刷新**（如 `落盘 xlsx 12.4 / 28.6 MB`、`落盘 pdf 6.1 / 15.2 MB`），不再只显示"落盘中"；
- 进度以右下角**后台任务面板**（§4.9）为主展示，生成弹层只是其中一个明细视图；关闭弹层后任务继续，面板徽标持续显示「后台任务 1」；
- 取消：进度弹层与任务面板各有一个 `取消` 按钮，均调 `POST /api/tasks/{id}/cancel` → `cancel_event.set()`；生成阶段取消丢弃内存产物，**落盘阶段取消删除 `.tmp` 半文件但保留库中存档**（状态 `partial`，可「重试落盘」）；
- 完成：面板与结果区显示 `报告已存档并落盘`，列出 `report_id` 与两个文件，按钮 `打开 xlsx` / `打开 PDF` / `下载 PDF` / `打开所在目录`；
- 部分成功（入库成功、落盘失败或落盘被取消）：显示「已存档（#id），落盘失败：{原因}」+ `重试落盘`（启动新的后台任务，互不覆盖）；
- 失败：红色内联错误 + `查看日志`（展开最近 20 行生成日志）；
- 任务在服务端运行，**刷新页面 / 切换页签 / 关闭浏览器不中止任务**；重开页面自动接续显示运行中任务。

**历史报告（顶部页签 `报告存档`）**

- 列表：`#id`、生成时间、统计日期与小时、产量/NG、xlsx/pdf 大小、落盘状态（已落盘 / 仅存档）；
- 操作：`下载 xlsx`、`下载 PDF`（从库流式返回，不依赖磁盘文件）、`重新落盘`、`打开文件`、`删除`（二次确认）；
- 默认按 `created_at` 倒序，可按日期筛选；顶部显示存档总占用（份数 + MB）。

**草稿与恢复（存数据库）**

- 存储：`report_drafts` 表（`day` 主键 + `hours` + `payload_json` + `updated_at` + `updated_by`），payload 含：小时列表、表头字段、每站原因文本、每站选中的图片 `ts`、每站「其他NG」、每站关联工单 id、实物图片列开关、操作人；
- **自动保存：每 5 分钟一次**（页面右上角显示倒计时：「下次自动保存 04:37 后」）；另外三类操作**立即保存**——切换工站/打 tag/删图后的关键变更（防抖 2s）、点「保存草稿」、点「生成报告」前强制保存；
- 保存失败（库断开）：右上角变红「保存失败，重试中」，每 30s 重试；生成按钮禁用并提示，避免"写了半小时内容丢了"；
- 重新打开同一日期自动恢复，顶部提示「已恢复 18:32 的草稿（操作人：产线工程师）/ 使用最新数据」；
- 同一日期只保留 1 份草稿；保存时携带基线 `updated_at` 做乐观锁：服务端发现已被他人更新则返回 409，页面提示「草稿已被 18:40 的会话更新，是否覆盖？」，默认不覆盖、可点「载入最新」；
- 生成成功后草稿默认保留（便于追加/重做），可在页面「报告存档」里手动清除；草稿不参与 `purge_reports` 清理。

**实现约束**

- HTTP 线程不得直接创建 tkinter 控件（现有约定），也**不得执行耗时的生成/落盘循环**：一律投递到后台任务队列（§4.9），接口只返回 `task_id`；
- 生成/落盘任务投递到 **单线程 executor**，串行执行，天然防并发写同名文件；
- 落盘按 1MB 分块写 `.tmp` 并上报字节进度，每块检查一次取消标志（§5.3 原子写）；
- `storage` 所有读写走现有 `StorageBase`（内部已加锁），页面查询与采集写入互不阻塞；
- 请求体限制 1MB（标注 Base64 图片走服务端取图，不由前端回传原图）；
- 端口就绪后写一个 `reports/.web_port` 文件，便于外部脚本/快捷方式定位。

### 4.4 处理流程

```
桌面[生成改善报告…] → ReportEntryDialog（日期默认当日 + 小时勾选）→ webbrowser.open(/report?date=&hours=)
  └─ 页面载入：GET /api/dates、/api/config、/api/summary、/api/draft?date=
       └─ 工程师看图打 tag / 画框 / 写原因 / 关联工单
            └─ 草稿每 5 分钟自动 POST /api/draft（关键操作即时保存）

页面[生成报告] → 先强制保存草稿 → POST /api/report/generate（参数 + 草稿快照）→ 202 {task_id}（页面不阻塞）
  └─ 后台单线程 executor → build_daily_report()（每次 IO 后上报 progress / 检查 cancel）
       ├─ 1. 聚合统计：按小时段 + 工站/相机取 C11 计数、OK/NG、job
       ├─ 2. 取图：页面已选图片（优先）或默认算法选取 → 缩略 JPEG
       ├─ 3. 生成工作簿：表头 → 逐站写行 → 合并 → 样式
       ├─ 4. 注入图片：WPS DISPIMG 嵌入单元格（§5.1 / §6.6）
       ├─ 5. 写「数据核对」Sheet + 脚注（含统计时段）
       ├─ 6. 渲染 PDF：A3 横版单页、米黄底（§5.4）
       ├─ 7. **入库**：reports + report_files（分块 BLOB，单事务提交）
       ├─ 8. **落盘 xlsx**：库 → `.tmp` → os.replace（1MB/块上报字节进度，可取消）
       ├─ 9. **落盘 pdf**：同上
       └─ 10. 更新 saved_path/saved_at → 任务 status=done，面板与弹层显示结果
```

关键顺序约束：**先入库、后落盘**。落盘失败不回滚入库记录（文件可随时用「重新落盘」补），避免"文件生成了但库里没有、事后无法追溯"。

### 4.5 图像选取算法（核心）

**优先采用页面已选图片**：草稿中该站已勾选/保留的图片 `ts` 列表非空时，直接按该列表取图（与页面所见一致）；仅当未选择时走下述自动算法。

**NG 图（M..X 列，每站 ≤ 上限）**

1. 取该相机**选中小时段内** `C11` 中 `ok=0` 的记录，得到 NG 时间戳集合 `T_ng`（升序）；
2. 对每个 `t ∈ T_ng`，在该相机 `A0` 图像中找 `|ts - t|` 最小且 `≤ 5s` 的一帧，作为该次 NG 的证据图；同一帧只使用一次（按 `ts` 去重）；
3. 若 `|T_ng| > 上限`：按时间轴把 `T_ng` **等距分段**，每段取最早的 1 张，保证覆盖所选时段而非集中在某一小时；
4. 读取图像统一走 `videocodec.load_images(storage, camera, "A0", start=?, end=?)`——该函数同时合并 `images` 原图与 `image_streams` AV1 分片解码结果，**不可直接查 `images` 表**（全库已被后台压缩，直接查会取不到图）；小时段不连续时分段调用并合并；
5. 缩略：等比缩放至长边 ≤ 设定值，转 JPEG(q=85)，单张目标 < 120KB；
6. 长宽比异常（宽高比 > 8 或 < 1/8）的图判为无效，跳过并记录。

**渲染图优先（图片口径）**：同一 `(camera, ts)` 若同时存在原图（`kind=image`）与渲染图（`kind=render`），**一律取渲染图**——渲染图是原图叠加了检测图形（判定框/阈值区）的结果，客户看到的框与图必须一致；仅当该帧渲染图缺失（老数据未生成 / 渲染失败）时回退 `kind=image` 原图，并在页面卡片角标与报告 `warnings` 中标注「原图」。页面缩略图缓存 key 需带 `kind`（如 `(camera, ts, kind, 长边)`）与报告取图 key 保持一致，避免渲染图与原图串用同一份缓存。

**OK 参考图（F 列，每站 1 张）**

- 取所选时段内 `ok=1` 的记录，取时间中位数附近最近一张 `A0`；无 OK 记录则不填（保持模板的"部分站留空"现状）。

**图片说明行**

- 有快速 tag 时写 `复核：{tag}（{reviewer}）`（如 `复核：误判（产线工程师）`）；无 tag 写 `实际NG`；
- 有画框标注但无 tag 时，追加第一条框的 `description` 摘要，最多 20 字；
- tag 计数汇总后参与 §3.3 的 I/J 计算。

### 4.6 原因分析（自动摘要 + 页面改写）

下行 `M{r+1}` 优先写**页面草稿中该站的原因文本**（工程师已审核过的对外结论）；草稿为空时才写自动事实摘要。摘要模板：

```
视觉NG {n} 件（不良率 {p:.1f}%）；检测项：{notes}；判定阈值：{lower}~{upper}；
统计时段：{hours}；NG 时段：{first_time}~{last_time}；配方：{jobs}；{连续NG提示}
```

- `{notes}` 取 `cameras.json` 中该相机 C11（或主判定单元格）的 `note`；
- `{连续NG提示}`：若存在连续 ≥ 3 件 NG，追加「{time} 起连续 {k} 件 NG，疑似工装/来料异常」；
- 全部为**事实陈述**，不含因果结论，避免把系统推测当成客户结论；
- 若所选时段内该站 NG = 0，写 `无 NG，维持现状`。

### 4.7 底部汇总

| 单元格 | 内容 |
|---|---|
| `B{last+1}` | `已调完:{n} 台`，n = 所选时段内有 OK 记录的相机数 |
| `B{last+2}` | `剩下:{m} 台`，m = 配置启用但所选时段内无记录的相机数 |
| `B{last+3}` | `合计：生产 {N} 件，NG {H} 件（{p:.1f}%）` |
| `B{last+4}` | 脚注（灰色 9pt）：统计时段小时列表 + 口径说明 + 生成时间 + 数据库类型（SQLite/MariaDB） |

### 4.8 工单管理与改善措施关联（类 GitHub Issue）

报告里的「原因分析及改造解决方案」本质是行动项，散在 Excel 里必然失联。本功能把每条改善措施落成**工单**：责任、状态、期限、验证结果集中管理，并可关联多份报告（复发时挂回同一单）。

**状态机**

```
open(开启中) ──开始处理──> in_progress(处理中) ──验证通过──> done(已完成) ──归档──> closed(已关闭)
     ↑                          │                              │
     └────────── 重新打开 ───────┴──────────────────────────────┘

closed 必须选择关闭原因：duplicate(重复) / wontfix(不处理) / invalid(误报) / fixed(已修复)
```

- 只有 `open` / `in_progress` 视为"未闭环"，会写入报告正文的原因分析；
- `done` / `closed` 不写正文，但保留在「工单跟踪」Sheet，向客户体现闭环；
- 状态流转全部记入时间线，不覆盖历史。

**字段**

| 字段 | 说明 |
|---|---|
| `id` | 自增，展示为 `#12`，报告与页面统一引用 |
| `title` | 一句话问题（如「OP20-1 焊缝反光误判」） |
| `body` | 问题描述（多行纯文本，保留换行） |
| `measure` | **改善措施**，与报告「原因分析及改造解决方案」对应，可反复编辑 |
| `status` | `open` / `in_progress` / `done` / `closed` |
| `close_reason` | `closed` 时必填 |
| `priority` | `P0~P3`，默认 `P2` |
| `category` | `misjudge`（误判优化）/ `product`（产品自身NG）/ `external`（外部原因）/ `other` |
| `station` / `camera` | 关联工站与相机（可空 = 全线） |
| `assignee` | 责任人（自由文本，默认 `视觉相关人员`） |
| `due_date` | 计划完成日（可空） |
| `created_by` / `created_at` / `updated_at` / `closed_at` | 自动维护 |

**工单页（页面新增页签 `工单`）**

- 列表仿 GitHub Issues：状态 Tab（开启中 / 处理中 / 已完成 / 已关闭 / 全部）+ 搜索（标题/正文/措施）+ 过滤（工站、类别、责任人、优先级）+ 排序（更新时间 / 优先级）；
- 行内：`#12 标题`、状态徽标（绿=开启中、蓝=处理中、灰=已完成、深灰=已关闭）、类别色点、工站、责任人、更新时间、关联报告数；
- 新建：`+ 新建工单` 右侧抽屉；从报告工作台新建时自动预填工站/类别/时段 NG 数/图片 ts 列表；
- 详情页：标题 + 正文 + 改善措施（就地编辑）+ 右侧属性栏 + 底部时间线（评论 / 状态变更 / 责任变更 / 关联报告，均带时间与操作人）；
- 快捷操作：`开始处理` / `完成` / `关闭`（选原因）/ `重新打开`、`关联报告`、`复制链接`（`http://{本机IP}:18110/tickets/12`，局域网内可互相打开）。

**与报告的双向关联**

1. 工作台右栏「原因分析」下方新增「关联工单」区：列出本站 `open/in_progress` 工单，勾选即纳入本报告；也可 `+ 新建工单`；
2. 关联存 `ticket_reports(ticket_id, report_id, station)` —— 一份报告可带多个工单，一个工单可挂多份报告；
3. 生成时每站原因文本末尾追加一行（仅未闭环工单）：

```
改善措施：#12 调整光源角度（处理中，责任人：张工，计划 11-15）；#15 更换吸盘（开启中）
```

4. 报告 Sheet 2「工单跟踪」列出本次涉及的全部工单（含已完成/已关闭，标状态与关闭原因），供客户查看闭环；
5. 工单详情页列出引用它的所有报告；报告存档被清理时显示「报告 #id 已清理（记录保留关联）」；
6. 生成后回写：`reports.payload_json` 快照中保存当时关联的工单与状态，保证历史报告可复现。

**自动建议（只提示，不自动开单）**

- 同站连续 ≥ 3 件 tag 为 `产品自身NG` → 右栏提示「建议开单：{站} 连续 NG」；
- 已存在同站同类别 `open` 工单 → 新建时改为「追加关联到 #12」，避免重复开单；
- 工单 `done` 后 7 天内同站同类 NG 再次出现 ≥ 阈值 → 列表与报告标注「可能复发」，并建议重新打开。

### 4.9 后台任务中心（页面右下角）

**任务模型**（服务端内存，`TaskManager`）

| 字段 | 说明 |
|---|---|
| `task_id` | `t-{YYYYMMDDHHmmss}-{seq}`，与 `report_id` 前缀区分 |
| `kind` | `generate`（生成+入库+落盘）/ `export`（重新落盘）/ `purge`（清理） |
| `title` | 展示名，如「生成 2026-11-10 报告（0-17 时）」 |
| `status` | `pending` / `running` / `done` / `partial` / `failed` / `canceled` / `interrupted` |
| `phase` | 当前阶段：`stats` / `images` / `xlsx` / `dispimg` / `pdf` / `store` / `save_xlsx` / `save_pdf` |
| `done` / `total` / `percent` | 阶段内进度；落盘阶段 `total` = 文件总字节 |
| `message` | 当前动作文案（含分块字节，如 `落盘 xlsx 12.4 / 28.6 MB`） |
| `cancelable` | 是否可取消（`done` 后为 `false`） |
| `result` / `error` | 成功：`{report_id, xlsx_path, pdf_path, sizes}`；失败/中断：原因 |
| `created_at` / `started_at` / `finished_at` | 时间戳 |

**队列与并发**

- 单线程 executor 串行执行，天然防并发写同名文件；提交即返回 `task_id`，等待中的任务 `status=pending`，面板显示「排队中」；
- 同一 `report_id` 的 `export` 去重：已有 `pending`/`running` 任务时直接返回该任务，不重复落盘；
- 任务只存内存，保留最近 20 条或 24 小时；服务重启时把残留 `running` 标记为 `interrupted`，页面提示「上次任务被中断，可重试」。

**UI（右下角悬浮面板，全页签可用）**

```
                        ┌─ 后台任务（1） ─────────────────────┐
                        │ 生成 2026-11-10 报告（0-17 时）      │
                        │ ████████████░░░░░░  落盘 pdf 63%    │
                        │ 落盘 pdf 6.1 / 15.2 MB      [取消]  │
                        ├─────────────────────────────────────┤
                        │ ✓ 重新落盘 #38（已完成）             │
                        │ ! 生成 11-09 报告（已存档，落盘失败） │
                        │                           [重试落盘] │
                        └─────────────────────────────────────┘
```

- 折叠态：右下角胶囊徽标 `后台任务 1`（运行中脉动），点击展开；无任务时隐藏；
- 每个任务一行：标题、进度条、当前动作、`取消`（`cancelable=true` 时）/ `重试` / `查看结果`；
- 完成 8s 后自动淡出；失败/中断保留到手动关闭；
- 生成弹层与任务面板共享同一份任务数据（同一 `task_id`），**关闭弹层不取消任务**；
- 完成后若停留在其他页签，徽标旁提示 `报告已生成`，点击跳「报告存档」。

**取消语义（按阶段）**

| 阶段 | 取消行为 |
|---|---|
| 统计 / 取图 / 建表 / DISPIMG / PDF | 立即抛 `CancelledError`，丢弃内存产物，状态 `canceled`，不写库、不落盘 |
| 入库（单事务） | 提交前检查取消；已提交则不再取消，转 `partial`，可继续落盘或重试 |
| 落盘 | 每写 1MB 检查一次；取消即删 `.tmp` 半文件，库中存档保留（`saved=0`），状态 `partial`，可「重试落盘」 |
| 已完成 | `cancelable=false`，不展示取消按钮 |

## 5. 输出规范

- 文件名：`视觉改善分析报告_{YYYYMMDDHHmmss}.xlsx` 与 `视觉改善分析报告_{YYYYMMDDHHmmss}.pdf`（同一时间戳成对生成，§5.3）；
- 标题行沿用项目名称（`{项目名称}视觉改善分析`），文件名统一用固定前缀，便于客户归档与检索；
- 保存位置：`{data_dir}/reports/`（不存在则创建）；**先入库后落盘**（§5.2）；
- Sheet 1：`{M月D日}`（与模板一致，如 `9月19日`）；
- Sheet 2：`工单跟踪`（可选，`include_ticket_sheet=True` 默认开）——列：工单号、标题、状态、关闭原因、类别、工站、责任人、计划完成日、创建/更新时间、改善措施摘要；
- Sheet 3：`数据核对`（内部用，交付客户前可删除）——列：相机、工站、C11 记录数、OK、NG、误判/产品自身NG/外部原因/未标注、首/末记录时间、当日配方、图源（原图/AV1）、缺失图数；
- 打印设置：A3 横向、缩放到 1 页宽 / 1 页高、冻结 `B4`、表头重复打印；
- 实物图片列：`include_physical_image=False`（默认）时 E 列 `hidden=True`，PDF 不占宽度也不绘制；列号不变，客户需要时取消隐藏即可补图；
- **脱敏**：不写相机 IP、端口、工控机路径、数据库连接串、日志内容、内部单元格地址（`A0`/`C11` 一律显示为「图像」「判定结果」）。

### 5.1 图片写入方式：原生 `DISPIMG` 嵌入单元格

参考模板中的图片是 WPS 的"嵌入单元格"图片，单元格内容为公式：

```
=_xlfn.DISPIMG("ID_301241C28D7E43CEAD6D645A1D1038BA",1)
```

**本项目直接由 Python 生成同款结构**（openpyxl 保存后再注入，见 §6.6），使报告在 WPS 中打开即是嵌入单元格效果：图片随单元格缩放/排序/筛选移动，不会像浮动图片那样错位。参考模板本身也是「openpyxl 生成 + 后处理注入」的产物（`docProps/app.xml` 记录 `Application = Microsoft Excel Compatible / Openpyxl 3.1.5`），说明该路径可行。

| 项 | 说明 |
|---|---|
| 实现 | `wpsdispimg.py`：`save → 注入 → 重打包`，约 120 行，仅用 `zipfile` + `xml.etree.ElementTree` |
| 嵌入对象 | F 列 OK 图、M..X 列 NG 图（E 列实物图默认隐藏，开启后同样以 DISPIMG 占位，由人工在 WPS 内替换） |
| 图片内容 | 写入单元格的是该帧**渲染图 JPEG**（图像 + 检测图形叠加，`kind=render`）；无渲染图时用原图并在该图角标注明「原图」。**不改变尺寸规则**：仍按 `image_max_edge` 等比缩放、单张目标 < 120KB |
| 兼容性 | **WPS 正常显示；Microsoft Excel 打开该单元格显示 `#NAME?`**（与参考模板行为一致，Excel 不识别 WPS 私有函数） |
| 兜底 | `report.json` 提供 `image_embed = "dispimg" \| "floating"`；`floating` 走 openpyxl 浮动图片（Excel/WPS 都能看，但会浮动）。默认 `dispimg`，页面生成前提示「客户使用 Excel 查看时请改为浮动图片」 |
| 不再需要 | 交付时手动「右键 → 嵌入单元格」的人工步骤 |

### 5.2 数据库存档（先入库）

每份报告在落盘前**完整写入数据库**，包含元数据与 xlsx/pdf 二进制，保证"文件丢了也能从库里重新导出"。

```sql
-- schema 版本（与软件版本号同一规则，见下方「schema 版本号规则」）
CREATE TABLE IF NOT EXISTS schema_meta (
    key        TEXT PRIMARY KEY,        -- schema_version
    value      TEXT NOT NULL,           -- 26.11.10.17
    updated_at TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS reports (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    day             TEXT NOT NULL,      -- 2026-11-10
    hours           TEXT NOT NULL,      -- "0,1,2,...,17"
    title           TEXT NOT NULL,      -- 项目名称视觉端NG原因分析
    filename        TEXT NOT NULL,      -- 视觉改善分析报告_20261110173210（不含扩展名）
    xlsx_size       INTEGER NOT NULL,
    pdf_size        INTEGER NOT NULL,
    xlsx_sha256     TEXT NOT NULL,
    pdf_sha256      TEXT NOT NULL,
    stations        INTEGER NOT NULL,
    products        INTEGER NOT NULL,
    ng              INTEGER NOT NULL,
    payload_json    TEXT NOT NULL,      -- 生成参数 + 每站草稿（原因/其他NG/选中图）
    created_at      TEXT NOT NULL,
    created_by      TEXT,
    saved_xlsx_path TEXT,               -- 落盘成功后回填
    saved_pdf_path  TEXT,
    saved_at        TEXT
);
CREATE INDEX IF NOT EXISTS idx_reports_day ON reports(day, created_at);
CREATE INDEX IF NOT EXISTS idx_reports_created ON reports(created_at);

-- 大字段分块：单块 ≤ 8MB，规避 MariaDB 默认 max_allowed_packet=16MB 限制
CREATE TABLE IF NOT EXISTS report_files (
    report_id INTEGER NOT NULL REFERENCES reports(id) ON DELETE CASCADE,
    kind      TEXT NOT NULL,            -- xlsx | pdf
    part_no   INTEGER NOT NULL,         -- 0..N
    data      BLOB NOT NULL,
    PRIMARY KEY (report_id, kind, part_no)
);

-- 快速 tag：按 ts 关联，不引用 images.id，避免阻塞 AV1 压缩
CREATE TABLE IF NOT EXISTS report_tags (
    day        TEXT NOT NULL,           -- 2026-11-10
    camera     TEXT NOT NULL,
    cell       TEXT NOT NULL DEFAULT 'C11',
    ts         TEXT NOT NULL,           -- NG 事件时间（与 samples.ts 一致）
    tag        TEXT NOT NULL,           -- misjudge | product | external
    reviewer   TEXT,
    note       TEXT,
    updated_at TEXT NOT NULL,
    PRIMARY KEY (day, camera, ts)
);
CREATE INDEX IF NOT EXISTS idx_report_tags_day_tag ON report_tags(day, tag);
CREATE INDEX IF NOT EXISTS idx_report_tags_cam_ts ON report_tags(camera, ts);

-- 网页草稿：一天一份，后写覆盖（每 5 分钟自动保存）
CREATE TABLE IF NOT EXISTS report_drafts (
    day         TEXT PRIMARY KEY,        -- 2026-11-10
    hours       TEXT NOT NULL,           -- "0,1,2,...,17"
    payload_json TEXT NOT NULL,          -- 表头/每站原因/选中图/其他NG/关联工单/开关
    updated_at  TEXT NOT NULL,
    updated_by  TEXT
);

-- 工单（改善措施）
CREATE TABLE IF NOT EXISTS tickets (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    title        TEXT NOT NULL,
    body         TEXT NOT NULL DEFAULT '',
    measure      TEXT NOT NULL DEFAULT '',
    status       TEXT NOT NULL DEFAULT 'open',   -- open|in_progress|done|closed
    close_reason TEXT,                          -- duplicate|wontfix|invalid|fixed
    priority     TEXT NOT NULL DEFAULT 'P2',     -- P0..P3
    category     TEXT NOT NULL DEFAULT 'other',  -- misjudge|product|external|other
    station      TEXT NOT NULL DEFAULT '',
    camera       TEXT NOT NULL DEFAULT '',
    assignee     TEXT NOT NULL DEFAULT '',
    due_date     TEXT,
    created_by   TEXT,
    created_at   TEXT NOT NULL,
    updated_at   TEXT NOT NULL,
    closed_at    TEXT
);
CREATE INDEX IF NOT EXISTS idx_tickets_status ON tickets(status, updated_at);
CREATE INDEX IF NOT EXISTS idx_tickets_station ON tickets(station, category);

-- 工单 ↔ 报告 多对多
CREATE TABLE IF NOT EXISTS ticket_reports (
    ticket_id INTEGER NOT NULL REFERENCES tickets(id) ON DELETE CASCADE,
    report_id INTEGER NOT NULL REFERENCES reports(id) ON DELETE CASCADE,
    station   TEXT NOT NULL DEFAULT '',
    created_at TEXT NOT NULL,
    PRIMARY KEY (ticket_id, report_id)
);
CREATE INDEX IF NOT EXISTS idx_ticket_reports_report ON ticket_reports(report_id);

-- 工单时间线（评论 / 状态变更 / 责任变更 / 关联报告）
CREATE TABLE IF NOT EXISTS ticket_events (
    id        INTEGER PRIMARY KEY AUTOINCREMENT,
    ticket_id INTEGER NOT NULL REFERENCES tickets(id) ON DELETE CASCADE,
    ts        TEXT NOT NULL,
    actor     TEXT,
    kind      TEXT NOT NULL,      -- created|comment|status|assign|link_report|measure
    payload   TEXT NOT NULL DEFAULT '{}'
);
CREATE INDEX IF NOT EXISTS idx_ticket_events_ticket ON ticket_events(ticket_id, ts);
```

| 设计点 | 说明 |
|---|---|
| 分块存储 | 30 台相机约 18~30MB/份，直接单 BLOB 插入会撞 `max_allowed_packet`；按 8MB 切片，读取时顺序拼接。SQLite 同样适用，行为一致 |
| 列类型 | MariaDB 侧 `data` 必须用 **`MEDIUMBLOB`**（`BLOB` 只有 64KB，8MB 块会截断/报错），SQLite 侧用 `BLOB`；由现有 `_typ()` 映射统一 |
| 事务 | `reports` + 全部 `report_files` 在同一事务提交；任一块失败整体回滚，不留半份 |
| 表创建 | 在 `StorageBase._init_schema()` 中 `CREATE TABLE IF NOT EXISTS`（`schema_meta` / `reports` / `report_files` / `report_tags` / `report_drafts` / `tickets` / `ticket_reports` / `ticket_events`），本次仅新增表、无需 ALTER；旧库启动自动补建。后续 DDL 变更走 schema 版本迁移（见下） |
| 草稿表 | 单日单份（`day` 主键），`payload_json` 存页面全部可恢复状态；不参与报告清理；生成成功后保留，供补做/重做 |
| 工单与清理 | 工单**不参与** `purge_reports`；报告被清理时 `ticket_reports` 随报告级联删除，工单本身保留（时间线保留，报告中显示「已清理」） |
| 快速 tag 独立表 | 不复用 `annotations`：后者以 `image_id` 外键关联 `images`，打标会迫使后台压缩**永久保留原图**；tag 只需 `ts`，天然不影响压缩，且同一 ts 唯一（取消 = 删除行） |
| 保留策略 | `report_keep_days`（默认 90）/ `report_keep_count`（默认 200），后台每日清理超额记录（含落盘文件）；`config/report.json` 可改 |
| 体积监控 | 数据库状态区新增「报告存档」项：份数 + 占用字节（`SUM(xlsx_size+pdf_size)`），与现有 AV1 压缩进度同排展示 |
| 删除 | `DELETE` 记录即级联删除分块；若已落盘，同时删除文件（需用户确认） |

#### schema 版本号规则（与软件版本号规则一致）

数据库 schema 版本号**不做自增整数，直接沿用软件版本号规则**：`{YY}.{MM}.{DD}.{N}`（与 `pyproject.toml` / `__version__` 同格式，如 `26.11.10.17`）。

| 项 | 规则 |
|---|---|
| 格式 | `YY.MM.DD.N`，四段全为整数；`YY.MM.DD` = 该次 schema 变更日期，`N` = 当日第几次 schema 变更（从 1 递增，与软件版本当日递增口径一致） |
| 何时递增 | **仅 DDL 变化时**（建表 / 加列 / 改列 / 加索引）才写入新值；不随每次软件发版改变，未改 schema 的新版本直接复用原值 |
| 存储位置 | `schema_meta` 表 `key='schema_version'`；不用 SQLite `PRAGMA user_version`（只能存整数，放不下四段版本），SQLite / MariaDB 行为一致 |
| 比较方式 | 按 `.` 拆成 4 个整数做元组比较（`26.11.10.2 > 26.11.9.30`），**禁止字符串比较**（`"26.11.9.30" > "26.11.10.2"` 会误判） |
| 启动流程 | `_init_schema()` 先 `CREATE TABLE IF NOT EXISTS` 全部表 → 读 `schema_meta`：为空（新库/旧库）写入当前版本；低于代码期望值则按版本升序执行增量迁移，成功后更新、失败回滚；高于代码期望值（旧程序打开新库）不迁移、不写入，只读启动并提示「数据库由更新版本创建，请升级程序」 |
| 迁移清单 | 现有 `_ensure_columns()` 补列逻辑作为特例保留；后续 DDL 变更按版本号顺序追加到迁移列表，每条幂等（可重复执行） |

### 5.3 落盘规则

- 目录：`{data_dir}/reports/`；
- 文件名：`视觉改善分析报告_{yyyyMMddHHmmss}.xlsx` 与 `视觉改善分析报告_{yyyyMMddHHmmss}.pdf`，**两份共用同一时间戳**，便于成对归档；
- 同秒冲突：追加 `_2`、`_3`；
- 原子写：先写 `{name}.tmp` → `os.replace()`，中途失败不留半文件；
- **分块写 + 进度**：每 1MB 写一次并回调任务进度（`落盘 xlsx 12.4 / 28.6 MB`），每块检查 `cancel_event`；取消/失败即删除 `.tmp`，已写部分不 `os.replace`；
- 两个文件串行落盘（xlsx → pdf），各自独立阶段 `save_xlsx` / `save_pdf`，任一失败不影响已完成的一个；
- 写后校验：重新计算 sha256 与库中记录比对，一致才回填 `saved_*_path` / `saved_at`；
- 落盘失败或被取消：报告仍在库中（`report_id` 可用），任务状态 `partial`，页面显示「已存档，落盘失败：{原因}」+「重试落盘」按钮；
- 重新落盘：`POST /api/reports/{id}/export`（后台任务），从库读流写回磁盘，用于误删、换机、拷贝到 U 盘。

### 5.4 PDF 交付版（A3 横版单页 · 米黄纸底）

PDF 与 xlsx **共用同一份布局模型**（`report.py` 产出 `LayoutModel`：行/列/单元格/图片矩形），xlsx 交给 openpyxl + DISPIMG 注入，PDF 交给 `pdfrender.py` 直接绘制 —— 两者数据与文字必然一致，不再维护第二套排版逻辑。

| 项 | 规格 |
|---|---|
| 页面 | A3 横向 420×297 mm（1190.55×841.89 pt），页边距 8 mm |
| 纸张底色 | 整页铺米黄 `#FBF3DC`（含页边，模拟米黄色纸张打印效果） |
| 表格线 | `#C9C2A6` 0.5pt，外框 1.0pt 深灰 |
| 表头 | 填充 `#00B050`、白色加粗字体，与 xlsx 一致 |
| 图片 | 直接嵌入生成时的 JPEG 字节（不依赖 WPS 引擎），在单元格区域内等比居中，白边留空 |
| 列显隐 | E 列实物图片默认不绘制（与 xlsx 的 `hidden=True` 一致）；开启后绘制同宽空列 + 浅灰「实物图片」字样，便于打印后粘贴 |
| 一页约束 | 按 `s = min((W-2m)/CW, (H-2m-页脚)/CH)` 整体缩放；`s < 0.55` 时先递减每站图片数（最小 1 张），再缩字号，最小 5pt；仍溢出则记为告警并在页脚注明「已压缩至 1 页」 |
| 页脚 | 左：`视觉改善分析报告`；中：`统计时段 {hours} · 生成于 {ts}`；右：`第 1 页 / 共 1 页` |
| 字体 | 复用 `assets/*.ttf`（Smiley Sans / 朱雀仿宋）注册后**子集嵌入**；缺失时回退系统微软雅黑 |
| 引擎 | `reportlab`（新增依赖，纯本地渲染，无 Office/WPS 依赖） |
| 可选引擎 | `report.json` 的 `pdf_engine = "reportlab" \| "com"`；`com` 用 WPS/Excel COM 导出，仅用于"必须与 WPS 打印像素一致"的场景，需处理后台启动、`#NAME?` 与授权提示 |
| xlsx 打印设置 | 同步设置 `paperSize=A3`、横向、`fitToWidth=1`、`fitToHeight=1`、打印区域、水平居中、页脚；表格区域填充 `#FBF3DC` 使 WPS 直接打印时也接近米黄底 |

> 为什么不用「xlsx → 转 PDF」：LibreOffice 不认 `DISPIMG`（图全丢）；WPS/Excel COM 依赖本机安装、易弹窗/授权/黑框，且工业机长期无人值守不稳定。直接渲染是唯一可控路径。

```sql
SELECT camera, cell, COUNT(*) AS total,
       SUM(CASE WHEN ok=1 THEN 1 ELSE 0 END) AS ok_cnt,
       SUM(CASE WHEN ok=0 THEN 1 ELSE 0 END) AS ng_cnt,
       MIN(ts), MAX(ts)
FROM samples
WHERE cell=? AND ok IS NOT NULL
  AND ((ts>=? AND ts<?) OR (ts>=? AND ts<?))
GROUP BY camera, cell
```

### 6.5 Web 服务与后台任务队列

```python
# web.py
class ReportServer:
    def __init__(self, storage, camera_cfgs, settings, data_dir, cfg: ReportConfig): ...
    def start(self) -> int:      # 返回实际端口；端口被占用时 +1 顺延（最多 20 次）

# tasks.py
class Task:                      # 数据即 §4.9 任务模型
    id: str; kind: str; title: str
    status: str; phase: str
    done: int; total: int; message: str
    cancelable: bool; result: dict | None; error: str | None
    cancel_event: threading.Event
    def to_dict(self) -> dict: ...

class TaskManager:
    def submit(self, kind, title, fn, *, dedupe_key=None) -> Task:
        """投递到单线程 executor，立即返回 Task；dedupe_key 相同且未结束则复用"""
    def get(self, task_id) -> Task | None: ...
    def list(self, active_only=False, limit=20) -> list[Task]: ...
    def cancel(self, task_id) -> bool: ...
    def mark_interrupted(self) -> None:   # 服务启动时把残留 running 标为 interrupted
```

| 关注点 | 设计 |
|---|---|
| 路由 | 手写 `SimpleHTTPRequestHandler` 子类，`do_GET` / `do_POST` 按 path 前缀分发；未知路径 404，非本机来源 403 |
| 静态页面 | `/report` 读取 `webui/` 下文件（`_MEIPASS` 兼容），`Cache-Control: no-store` 便于改版即生效 |
| 图片接口 | `/api/image/...` 现场取图：`videocodec.load_images` 单帧 → `PIL` 缩到 `w` → `image/jpeg`；带 `ETag = camera+ts+w`，浏览器缓存命中不再解码 |
| 并发 | `ThreadingHTTPServer` + `daemon_threads=True`；图片解码自身有锁保护（`load_images` 内部 cache 仅本地变量，安全） |
| 后台任务 | `TaskManager` 单线程 executor 串行执行；`POST /api/report/generate`、`/api/reports/{id}/export` 均只投递并返回 `202 {task_id}`，HTTP 线程不做生成/落盘 |
| 进度 | 任务对象内原子更新 `phase/done/total/message`；页面 500ms 轮询 `/api/tasks?active=1`（轮询优于 SSE：产线浏览器/杀毒代理对长连接不友好） |
| 落盘进度 | `reportstore.save_report()` 按 1MB 分块写 `.tmp`，每块回调 `progress("save_xlsx", written, total, "落盘 xlsx 12.4 / 28.6 MB")`，并检查 `cancel_event` |
| 取消 | `POST /api/tasks/{id}/cancel` → `task.cancel_event.set()`；生成函数在阶段检查点抛 `CancelledError`；落盘取消删 `.tmp`、保留库中存档（§4.9） |
| 任务可见性 | 任务在服务端运行，前端刷新/关页不影响；页面重开从 `/api/tasks` 自动接续显示；结果保留 20 条/24h |
| 日志 | 生成过程的 warning/error 存环形缓冲（最近 200 行），供页面「查看日志」；同时正常写 `logging` |
| 端口文件 | `reports/.web_port` 写入实际端口，供快捷方式/脚本使用 |
| 安全 | 监听 `0.0.0.0` 供局域网访问；`POST` 校验 `Origin` 为本机回环或本机局域网 IP（空 Origin 需 `X-CTM-Token`）；`web_token` 可选口令；敏感操作（删除存档/打开文件/导出打开目录/退出/`open_entry`）仅回环地址可用，远程 403；`os.startfile` 仅允许打开 `reports/` 下的文件 |

### 6.6 WPS `DISPIMG` 注入实现（关键）

**调用时序**：`openpyxl` 正常建表并 `wb.save(path)` → `wpsdispimg.embed_cell_images(path, items)` 重写 zip。**不能**在 `Workbook` 对象上改包（下次 `save()` 会覆盖），顺序不可颠倒。

```python
# wpsdispimg.py
@dataclass
class CellImage:
    cell: str          # "E4" / "M10"
    data: bytes        # JPEG/PNG 原始字节
    ext: str = "jpeg"  # jpeg | png
    descr: str = ""    # 可选，cNvPr 的 descr（WPS 显示为图片描述）

def embed_cell_images(xlsx_path: Path, items: list[CellImage]) -> None
```

**写入的 6 个部件**（实测自参考模板）：

1. **媒体文件** `xl/media/image{n}.{ext}`（n 取现有最大值 +1，避免与浮动图冲突）；
2. **`xl/cellimages.xml`**（新增）：

```xml
<?xml version="1.0" encoding="UTF-8" standalone="yes"?>
<etc:cellImages
    xmlns:xdr="http://schemas.openxmlformats.org/drawingml/2006/spreadsheetDrawing"
    xmlns:r="http://schemas.openxmlformats.org/officeDocument/2006/relationships"
    xmlns:a="http://schemas.openxmlformats.org/drawingml/2006/main"
    xmlns:etc="http://www.wps.cn/officeDocument/2017/etCustomData">
  <etc:cellImage><xdr:pic>
    <xdr:nvPicPr>
      <xdr:cNvPr id="1" name="ID_301241C28D7E43CEAD6D645A1D1038BA" descr="OP10-1 NG"/>
      <xdr:cNvPicPr><a:picLocks noChangeAspect="1"/></xdr:cNvPicPr>
    </xdr:nvPicPr>
    <xdr:blipFill><a:blip r:embed="rId1"/><a:stretch><a:fillRect/></a:stretch></xdr:blipFill>
    <xdr:spPr>
      <a:xfrm><a:off x="0" y="0"/><a:ext cx="3810000" cy="2857500"/></a:xfrm>
      <a:prstGeom prst="rect"><a:avLst/></a:prstGeom>
      <a:noFill/><a:ln w="9525"><a:noFill/></a:ln>
    </xdr:spPr>
  </xdr:pic></etc:cellImage>
</etc:cellImages>
```

   - `cNvPr/@id`：文档内唯一的正整数（全局自增即可，参考文件并不连续）；
   - `cNvPr/@name`：`ID_` + **32 位大写十六进制**，公式里的 ID 必须与它完全一致，否则 WPS 显示空白；
   - `a:blip/@r:embed`：指向 `cellimages.xml.rels` 的 `rId`；
   - `a:ext/@cx|cy`：图片像素 × 9525（EMU），仅记录原始尺寸；单元格内展示由 WPS 按单元格自适应。

3. **`xl/_rels/cellimages.xml.rels`**（新增）：

```xml
<Relationships xmlns="http://schemas.openxmlformats.org/package/2006/relationships">
  <Relationship Id="rId1"
    Type="http://schemas.openxmlformats.org/officeDocument/2006/relationships/image"
    Target="media/image63.jpeg"/>
</Relationships>
```

4. **`[Content_Types].xml`** 增加 Override（否则 WPS 认为部件非法）：

```xml
<Override PartName="/xl/cellimages.xml"
          ContentType="application/vnd.wps-officedocument.cellimage+xml"/>
```

5. **`xl/_rels/workbook.xml.rels`** 增加关系（`Id` 取未占用的 `rIdN`）：

```xml
<Relationship Id="rId99"
  Type="http://www.wps.cn/officeDocument/2020/cellImage"
  Target="cellimages.xml"/>
```

6. **工作表单元格**改写为公式（保留原 `s` 样式索引，新增 `t="str"`）：

```xml
<c r="E4" s="16" t="str">
  <f>_xlfn.DISPIMG("ID_301241C28D7E43CEAD6D645A1D1038BA",1)</f>
  <v>=DISPIMG("ID_301241C28D7E43CEAD6D645A1D1038BA",1)</v>
</c>
```

**实现要点（踩坑清单）**

| 坑 | 处理 |
|---|---|
| 命名空间前缀污染 | `ET.register_namespace("", 主命名空间)`；`cellimages.xml` 用字符串模板生成，不经 `ET` 序列化，确保 `etc:` 前缀与参考文件一致 |
| `standalone="yes"` | 手写 XML 声明头，`ET.tostring` 默认不带 |
| 公式引号转义 | 交给 `ET` 写 `<f>`，自动转成 `&quot;` |
| 目标单元格原本为空 | openpyxl 会输出 `<c r="E4" s="16"/>`；按 `r` 属性定位后追加子节点即可，不要重建整行 |
| 单元格已合并 | 只允许写入合并区左上角单元格（报告布局中 E/F/M.. 均为非合并单元格，无需处理） |
| 行高 | `DISPIMG` 不改变行高，需在 openpyxl 阶段就设 `row_dimensions[r].height = 90`，否则图片被压扁 |
| 图片过大 | 入库前统一 `PIL` 缩到长边 ≤ `image_max_edge`、JPEG q=85；单张 > 500KB 再降一档 |
| 重打包 | 按原成员顺序写回，`ZIP_DEFLATED`；先写临时文件再 `os.replace`，避免中途失败损坏原文件 |
| 校验 | `zipfile.testzip()`；对改动的 4 个 XML 逐个 `ET.fromstring` 解析；再用 `openpyxl.load_workbook` 读回确认单元格为公式字符串 |
| Excel 打开显示 `#NAME?` | 已知行为，与参考模板一致；`image_embed="floating"` 可切换为浮动图片 |

> 该步骤独立于报告业务逻辑，可先用 1 张图做最小验证：生成 → WPS 打开 → 确认图片在单元格内、缩放列宽时随单元格变化。

### 6.7 性能与资源

| 场景 | 预估 |
|---|---|
| 30 台相机 / 全天 8000 条判定 / 每站 6 张 NG 图 | 查询 < 1s；AV1 解码约 1.5s/分片，命中缓存的同分片只解一次；总耗时 15~30s |
| 页面首屏（30 站汇总 + 首站 6 张缩略图） | ≤ 1.5s（缩略图 320px，服务端缓存在内存 LRU，命中即 10ms 内返回） |
| 报告体积 | 每张图 ~100KB × 180 张 ≈ 18MB；关掉 OK 图或降上限可压到 8MB 内 |
| PDF 渲染（A3 单页、180 张图） | 1~2s（reportlab 直接绘制，无外部进程） |
| 入库（xlsx + pdf 约 40MB，8MB 分块） | 本机 MariaDB 1~3s；SQLite 0.5~1s |
| 落盘（原子写 + sha256 校验） | < 0.5s |
| 内存 | 图像逐张读、写入后立即释放，峰值 ≈ 单张解码结果 + Workbook + 分块缓冲；禁止一次性 `load_images` 全站全量 |

优化点：按「相机 + 时间窗」分批取图；同一 AV1 分片在同一批次内只解码一次（`load_images` 已实现 cache）。

## 7. 边界与异常

| 场景 | 处理 |
|---|---|
| 小时勾选为空 | 页面「生成报告」置灰，提示「请至少勾选 1 个统计小时」；后端接口同样返回 400 |
| 所选小时跨 0 点（如勾 22、1） | 按同日的小时处理，形成 `(22:00,23:00)` 与 `(01:00,02:00)` 两段；跨日需求通过切换日期 + 分两次生成实现（不做跨日合并，避免口径歧义） |
| 当日无任何 `C11` 记录 | 页面提示「该时段无生产数据」，提供「仍生成空表模板」二次确认 |
| 某相机时段内无 A0 图像（相机未连/停用） | 该站数量正常填，图片区写「无图像」，`数据核对` 中记 `缺失图数` |
| `images` 与 `image_streams` 均无数据 | 跳过图片，继续生成，告警计入 `warnings` |
| 渲染图缺失（老数据未生成 / 渲染失败） | 回退该帧原图（`kind=image`），页面卡片与报告该图角标注明「原图」，`warnings` 记一条；不阻塞生成 |
| 渲染图与原图尺寸不一致 | 以**渲染图实际像素**为准，标注坐标、缩略图与报告嵌入图使用同一张同一尺寸，不再做二次缩放对齐（避免框偏移） |
| ffmpeg 缺失 | 只用原图；报告中脚注说明；不阻止生成 |
| 数据库在生成中断开 | 捕获异常 → 页面显示「数据库连接异常，请检查后重试」；未提交事务自动回滚，不产出半份存档 |
| 磁盘空间不足 | 落盘异常捕获 → 提示目标目录不可写/空间不足；库中存档保留，可「重试落盘」 |
| 用户中途取消 | `cancel_event.set()`；每 20 张图/500 行检查一次；丢弃内存产物，不写库、不落盘 |
| 重复提交 | 单线程 executor + 运行中任务标记，第二次返回 409；页面「生成报告」在运行中变「取消」 |
| 端口 18110 被占用 | 依次尝试 +1~+20；全部失败则回退「不启动服务」，桌面端提示「报告工作台端口不可用」 |
| 浏览器无法启动 | `webbrowser.open` 返回 False 时，桌面端弹窗给出完整地址，供手工粘贴 |
| DISPIMG 注入失败 | 记录错误 → **自动降级为浮动图片**并重存一次（保证一定能出文件），页面提示「已降级为浮动图片」 |
| 目标图已被 AV1 压缩、ffmpeg 不可用 | 该帧跳过并在 `数据核对` 标记，不阻塞其它图；**tag 仍可打**（只按 `ts` 记录），统计与「复核」文案不受影响 |
| 快速 tag 与已有 tag 冲突 | 同一 `(day, camera, ts)` 主键 UPSERT，最后写入生效；页面用接口返回值刷新颜色，不做本地猜测 |
| 取消 tag | 删除 `report_tags` 行；报告该图恢复 `实际NG`，I/J 重新按 §3.3 计算 |
| tag 总数 > NG 总数（重复打标/历史残留） | 按 H 截断并写入 warnings，保证 `I ≥ 0`、`I + J = H` |
| 手工填写其他NG 与 tag 汇总不一致 | 手工值优先，脚注标注「其他NG含人工调整」，`数据核对` 同时给出 tag 汇总值供对比 |
| 关闭工单未选原因 | 前端必选 + 后端 400 拒绝，不落库、不记时间线 |
| 同一报告重复关联同一工单 | `ticket_reports` 主键幂等，重复请求返回成功且不新增行 |
| 工单关联的报告被清理 | 关联行随报告级联删除；工单时间线保留一条「报告 #id 已清理」记录，详情页显示为灰色 |
| 删除工单 | 二次确认（提示将删除关联与时间线，不可恢复）；不删除任何报告文件 |
| 两人同时编辑同一工单 | 以 `updated_at` 做乐观锁，冲突返回 409 并提示「已由 {actor} 更新，请刷新后重试」 |
| 单站关联工单 > 5 条 | 报告正文只列前 5 条 +「等 N 条」，完整列表写入 Sheet 2「工单跟踪」 |
| 报告生成后工单状态又变化 | 历史报告以 `payload_json` 快照为准，不回改文件；页面在报告详情提示「工单 #12 已更新」 |
| 工单统计未闭环数为 0 | 报告正文不追加「改善措施」行，Sheet 2 仍输出（可仅含已完成/已关闭） |
| 两个浏览器同时编辑同一天 | tag 走主键 UPSERT 无冲突；草稿用 `updated_at` 乐观锁（409 + 覆盖确认），不做实时协同 |
| 局域网其他工控机访问 | 正常：`http://{本机IP}:{端口}` 打开工作台（监听 `0.0.0.0`）；远程可标注 / 写草稿 / 生成；删除存档、打开文件、退出、`open_entry` 等敏感操作返回 403 |
| 远程访问被拒 / 超时 | 多为 Windows 防火墙未放行端口：状态栏提示放行**专用网络**；核对 `web_host=0.0.0.0`、IP 与网段是否正确 |
| 多客户端同时编辑同一天草稿 | `updated_at` 乐观锁：后保存者若基线过期则收到 409，提示「他人已更新，是否覆盖」，默认保留服务端版本 |
| Microsoft Excel 打开报告 | 图片单元格显示 `#NAME?`（WPS 私有函数）；交付前在页面选择 `floating` 模式即可 |
| **入库失败（库断开 / 磁盘满 / 分块超限）** | 整个事务回滚，不产生 `report_id`；页面提示「存档失败，未生成文件」，临时产物丢弃 |
| **入库成功但落盘失败** | 保留库记录，页面显示 `report_id` + 错误原因 + 「重试落盘」；不视为生成失败 |
| **PDF 渲染失败** | xlsx 正常入库落盘，`pdf` 置空（`pdf_size=0`），页面提示「PDF 生成失败，可稍后重试」；`/api/reports/{id}/export` 可单独补 PDF |
| 落盘目录被占用/只读 | 捕获 `PermissionError`，提示关闭占用程序后重试；不影响库中存档 |
| 同一秒重复生成 | 文件名追加 `_2`；库中两条记录各自独立，不覆盖 |
| PDF 内容溢出 1 页 | 按 §5.4 自动减图/缩字号；仍溢出则告警并附「已压缩至 1 页」，禁止生成第 2 页 |
| 存档超过保留策略 | 启动时 + 每日定时跑 `purge_reports`，删除超额记录与对应文件；页面提示清理条数 |
| 大库体积 | 数据库状态区显示报告存档占用；超过 `report_warn_bytes`（默认 2GB）在日志与状态区标黄提示 |
| 用户删除存档但文件仍被 WPS/PDF 阅读器占用 | 文件删除失败时只删库记录，文件保留并记日志（下次清理再试） |
| 相机名不含 OP 编号 | 不合并工站单元格，按独立站展示 |
| `C11` 大量 NULL（无判定） | 只统计 `ok IS NOT NULL` 的记录，并在脚注给出「无判定 {k} 条，未计入」 |
| 选了一个没有任何 NG 的历史日期 | 正常生成（NG 全 0，原因写「无 NG，维持现状」），禁止生成的条件只有"小时为空" |
| 选了未来日期 | 入口对话框不列出未来日期；接口层再校验一次（400），防止手改 URL 参数 |
| 所选日期数据已被清理（超出图像保留期） | 统计仍可出（`samples` 在），但取不到图：报告中对应单元格留空并在「数据核对」标注「无图」 |
| 草稿保存失败（数据库断开） | 右上角红色「保存失败，30s 后重试」，生成按钮禁用；草稿同时留在浏览器 `localStorage`，恢复后自动补传 |
| 升级后旧草稿兼容 | `payload_json` 缺失字段按默认值补齐（`payload.get(k, default)`），不因新增字段导致打不开 |
| 库中 schema 版本低于代码期望值 | 启动时按版本升序执行增量迁移（幂等），成功后更新 `schema_meta`；任一条失败则回滚并中止启动，提示「数据库迁移失败」+ 日志路径 |
| 旧程序打开新库（schema 版本高于代码期望值） | 不迁移、不写入，只读启动并提示「数据库由更新版本创建，请升级程序」，避免把新结构当旧结构写坏数据 |
| 页面 URL 参数缺失 | 日期默认今日、小时默认 `0..当前小时`，等价于从入口直接进入 |
| 生成/落盘过程中刷新或关闭页面 | 任务在服务端继续执行，不中断；重开页面从 `/api/tasks` 接续显示进度与结果，不重复生成 |
| 落盘中途取消 | 删除 `.tmp` 半文件，库中存档保留（`saved=0`），任务 `partial`，可「重试落盘」 |
| 落盘时进程被杀/断电 | 仅残留 `.tmp`；启动时清理 `reports/*.tmp`，库中 `saved_*_path` 为空可重新落盘 |
| 落盘时磁盘写满 | 捕获 `OSError`（ENOSPC）→ 删 `.tmp`，任务 `failed`，提示清理磁盘后「重试落盘」 |
| 同一报告重复点「重新落盘」 | `dedupe_key = report_id:export` 复用进行中任务，返回同一 `task_id`，不排队第二份 |
| 已有生成任务时再次提交 | 新任务 `pending` 排队，面板显示「排队中」；仅「同参数重复生成」返回 409 |
| 服务重启时存在 `running` 任务 | 启动调用 `mark_interrupted()`，面板提示「上次任务被中断，可重试」 |

## 8. 验收标准

1. **小时口径**：17:32 打开页面，默认勾选 `0..17`，`18..23` 置灰；选历史日期时 24 小时全部可选且默认全选；手工改勾 `8,9,10` 后，报告 G/H 列只统计这三小时，脚注显示「2026-11-09 08:00-11:00（共 3 小时）」；勾选为空时生成按钮不可用。
2. **日期**：入口对话框日期默认当日；下拉不含未来日期、只列有 `C11` 记录的日期；选历史日期生成后，报告日期、统计范围、图片均来自该日；同一天再次生成可产出第二份存档（id 不同、时间戳不同）。
3. **DISPIMG 嵌入**：WPS 打开生成文件，F/M.. 列图片**位于单元格内**（缩放列宽、插入行时随单元格移动），单元格编辑栏显示 `=DISPIMG("ID_...",1)`；开启实物图片列后 E 列同样可嵌入；切到 `floating` 模式则变为浮动图片且 Excel 也能看到。
4. 数据准确性：任选一天，报告 G/H/I 列与「数据核对」Sheet 的逐相机计数可复核一致；恒有 `I + J = H`（未打 tag 且未手工改 J 时 `I = H`、`J = 0`）。
5. 图像可用性：每站 NG 图数量 ≤ 上限，且全部来自所选时段 `ok=0` 时刻 ±5s 内；被 AV1 压缩过的历史图也能正常显示（关键回归点）。
6. **Web 工作台**：本机 `http://127.0.0.1:18110/report?date=...&hours=...` 与局域网 `http://{本机IP}:18110/report?...` 均可打开并按参数初始化；入口对话框与状态栏显示这两个地址且可复制；远程可标注/写草稿/生成，敏感操作 403；切换日期/小时会刷新工站与图片；点击图片能画框、填 label/说明并保存，重开页面仍能读回标注（写入 `annotations`）。
7. **草稿（数据库）**：改动后 5 分钟内自动写入 `report_drafts`（右上角倒计时可见）；关闭浏览器重开同一日期自动恢复，提示恢复时间与操作人；点击「保存草稿」立即入库；`GET /api/draft?date=` 返回的 payload 与页面状态一致；生成成功后草稿仍保留。
8. **快速 tag**：卡片上单击 `误判` / `产品自身NG` / `外部原因` 立即生效（刷新页面仍在）；再点取消；键盘 `1/2/3/0` 可用；三种 tag 互斥。
9. **tag 驱动口径**：某站 H=10、`误判`=2、`外部原因`=1、`产品自身NG`=5、未标注=2 → 报告中 I=7、J=3，且 `I+J=H`；「数据核对」四项计数一致；手工改 J 后 I 自动等于 `H-J`。
10. **实物图片默认隐藏**：默认生成的 xlsx 中 E 列为隐藏列（列宽与其他列保留）、PDF 不出现该列；页面勾选「显示实物图片列」后两者同步出现。
11. **所见即所得**：页面保留的 NG 图与报告 M..X 列顺序/内容完全一致；页面删除的图不出现在报告中。
12. 版面对齐：行高/列宽/表头绿底/2 行 1 站/工站纵向合并/底部「已调完/剩下」与参考模板一致。
13. 交互：点击入口 → 先出日期+小时对话框 → 确认后浏览器打开工作台；生成全程桌面主界面不卡顿；取消后无残留文件；重复点击生成返回 409 而非产出两份文件。
14. **先入库后落盘**：生成完成后 `reports` 有 1 条、`report_files` 有 xlsx/pdf 各自分块记录；磁盘上出现同时间戳的 `视觉改善分析报告_{ts}.xlsx` 与 `.pdf`，`saved_*_path` 已回填。
15. **库文件一致性**：删除磁盘文件后，通过 `/api/reports/{id}/export` 能原样恢复；恢复文件 sha256 与入库时一致。
16. **PDF 规格**：PDF 页数恒为 1，页面 420×297mm 横向，整页背景 `#FBF3DC`，图片完整可见，中文字体无方框，页脚含统计时段与生成时间。
17. 脱敏：文件中搜索不到 IP、`D:/JustSmart`、`A0`、`C11`、日志文本。
18. 兼容：SQLite 与 MariaDB 两种后端生成结果一致；旧版 `cameras.json`（无 `station`/`model` 字段）可直接使用；旧库启动自动补建 `schema_meta`/`reports`/`report_files`/`report_tags`/`report_drafts`/`tickets`/`ticket_reports`/`ticket_events` 八张表且不影响历史数据；打包为 exe 后 `webui/` 静态资源可正常加载。
19. 性能：30 台相机、单站 6 张 NG 图的典型工况下，生成 + 入库 + 落盘总耗时 ≤ 90s，单份 xlsx/pdf 各 ≤ 30MB。
20. **工单状态机**：新建（开启中）→ 开始处理（处理中）→ 完成（已完成）→ 关闭（不选原因被拒，选 `fixed` 后通过）→ 重新打开（开启中）；每次变更在详情页时间线各留一条记录，`updated_at` 随之刷新。
21. **工单↔报告**：工作台右栏勾选 `#12` 生成报告 → 该站原因文本末尾出现 `改善措施：#12 ...`；Sheet 2「工单跟踪」含该单状态；工单详情「关联报告」出现该报告；存档下载的 xlsx 与落盘文件内容一致。
22. **多对多**：同一工单关联第二次日报告后，详情页列出两份报告；同一报告重复关联同一工单不产生重复行。
23. **复发提示**：工单 `done` 后 7 天内同站同类 NG 再次出现并超过阈值 → 工单列表与报告页面显示「可能复发」。
24. **清理联动**：删除报告存档后，工单仍在列表；其详情页原报告条目显示「报告 #id 已清理」。
25. **schema 版本号**：`schema_meta.schema_version` 与软件版本同格式（`YY.MM.DD.N`）；新建库写入当前值；改 DDL 后旧库启动能按版本升序迁移并更新；版本比较按四段整数（`26.11.10.2 > 26.11.9.30`）；旧程序打开新库进入只读模式并提示升级。
26. **后台任务与落盘进度**：点「生成报告」后 HTTP 立即返回、页面仍可编辑；右下角任务面板显示阶段与百分比，落盘阶段显示 `x / y MB` 字节进度；关闭生成弹层任务继续；刷新页面后仍能接续显示运行中任务并最终给出结果。
27. **取消（落盘）**：生成阶段取消 → 库中无记录、磁盘无文件；落盘阶段取消 → 仅删 `.tmp`，库中存档保留、任务 `partial` 且显示「已存档，落盘失败（已取消）」+「重试落盘」可成功；已完成任务不显示取消按钮。
28. **渲染图口径**：网页展示（缩略图/大图）与报告嵌入的均为 `kind=render` 渲染图；渲染图缺失时回退原图并在页面卡片与报告该图角标注明「原图」；画框标注坐标与报告图片像素一致（同一张图、同一尺寸），切换站点/刷新后框位置不偏移。

## 9. 非目标

- 不做自动缺陷分类/自动归因（不猜测"找线错误"这类结论）；
- 不做 PPT 输出；
- 不接入客户 MES 的产品序列号对齐（跨相机产品关联留待有扫码数据后再做）；
- 不替代现有「导出xlsx」（后者是工程师用的全量数据明细，本功能是客户向汇总材料）；
- 报告存档不做多用户/权限体系（本机单用户使用，操作人仅作署名）；
- 工单不发通知（邮件/短信/IM/飞书）、不做工时与成本核算、不做附件上传、不做甘特图；
- 工单与客户方系统不做同步（仅本机数据库）。

## 10. 实施顺序（建议）

0. **`mocks/` 原型先行**：纯静态 HTML/CSS/JS 实现「改善报告工作台」与「工单」两个页面（假数据、localStorage 持久化、可交互），先确认信息架构与交互流程，再进入真实实现；原型与本设计共用同一套信息结构，落地时替换数据源即可；
1. `config.py` 增加 `station`/`station_name`/`model` 与 `AppSettings.project_name/destination/line_name/web_host/web_port/web_token`；`storage.py` 增加 3 个 `range_*` 聚合方法 + `schema_meta`/`reports`/`report_files`/`report_tags`/`report_drafts`/`tickets`/`ticket_reports`/`ticket_events` 建表与 CRUD，并实现 schema 版本号读写与四段整数比较（见 §5.2）（用真实数据验证 SQL 与 `hour_ranges` 分段正确）；
2. `report.py` 先实现无图版本（小时统计 + `LayoutModel` + 版面 + 样式），与参考模板逐格对齐；
3. **`wpsdispimg.py` 独立先行**：用 1~2 张图做最小验证（生成 → WPS 打开 → 单元格内显示、缩放列宽跟随），再接入报告；
4. 接入 `videocodec.load_images` 插 NG/OK 图（含 AV1 解码路径），验证历史压缩数据；
5. **`pdfrender.py`**：从同一 `LayoutModel` 渲染 A3 横版单页 + 米黄底，验证中文字体、图片缩放与一页自适应；
6. **`reportstore.py`**：入库（分块 + 事务）→ 落盘（1MB 分块 + 原子写 + 字节进度 + 可取消 + sha256 校验）→ 重新导出 → 保留清理；同步实现 **`tasks.py`** 通用后台任务管理器（单线程队列、进度回调、取消、`dedupe_key`、`interrupted` 恢复），先用脚本验证「提交 → 进度 → 取消 → partial」四种状态；
7. **工单**：先落 `tickets` 的状态机与 `ticket_events`（脚本级单测），再做工单页（列表/详情/时间线/评论），最后接报告（右栏勾选、正文追加、Sheet 2 输出、双向关联）；
8. `web.py` + `webui/`：先做只读（配置、汇总、工站、图片），再做标注、草稿、生成（后台任务 + 进度/取消 + 右下角任务面板）、历史报告列表与下载、工单页；
9. `ui.py` / `tray.py` / `app.py` 接入入口与生命周期（启动起服务、退出停服务）；
10. 以真实一天数据与客户模板逐格对比，确认 WPS、Excel（floating）与 PDF 三种打开方式；
11. 补 `README.md`：输出口径、小时勾选、报告存档与落盘规则、DISPIMG 与 Excel 的差异、工单闭环说明。
