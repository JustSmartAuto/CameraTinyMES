# 跨网段相机互通方案（A/B 工控机）

> 场景：本软件部署在工控机 A（192.168.10.0/24），需要采集只挂在工控机 B（192.168.20.0/24）上的相机。
> A、B 之间用独立网卡直连（192.168.8.0/24，静态 IP）。
> 相机清单依据：`D:/JustSmart/261028艾龙锦恒SAB自动线/相机及工控机统计/CAB/CAB相机及工控机统计.xlsx`。

## 2. 本软件访问相机的方式（决定方案边界）

| 用途 | 协议 | 目标 | 发起方 | 说明 |
|---|---|---|---|---|
| 建立会话 / 结果改变通知 | WebSocket | `ws://相机:80/ws` | A（软件） | 每台一条长连接，断开后 5s 自动重连 |
| 取原始图像 | HTTP GET | `http://相机:80/cam0/img/...` | A（软件） | 可带 `?sz=640,480` 请求缩放版 |
| 取 SVG / 图形图层 | HTTP GET | `http://相机:80/cam0/app/views/...` | A（软件） | 仅在 HMI 会话存活期间有效 |
| 取点云 | HTTP GET | `http://相机:80/cam0/pc/...` | A（软件） | CPCD 二进制，超时 60s |

三个关键结论，直接决定了方案选型：

1. **全部是 A 主动发起的出站连接**（TCP），相机从不反向连 A → 只需要「A → B → 相机」单向可达，无需端口映射到 A。
2. **WebSocket 与 HTTP 共用同一个 TCP 端口 80** → 只做 TCP 端口转发即可同时覆盖两者。
3. **相机返回的图层/图像地址都是根相对路径**（实测 `/cam0/app/views/001000000000171`、`/cam0/img/000000000000084`），程序用「相机 host + port」拼完整 URL → **换成 B 的地址 + 映射端口后仍然成立**，不会出现「图片地址仍指向 192.168.20.x」的断链。

## 3. 方案对比

| 方案 | 原理 | 需要改什么 | 主要风险 | 结论 |
|---|---|---|---|---|
| **A. B 上做 TCP 端口转发（portproxy）** | B 监听 `192.168.8.2:20031`，转发到 `192.168.20.31:80` | 仅 B 上 15 条转发规则 + 防火墙；A 改 `cameras.json` 的 host/port | 极低，不动路由、不动相机、不动产线 | **推荐** |
| B. A 加静态路由 + B 开 IP 转发 | A：`route add 192.168.20.0/24 via 192.168.8.2`；B：开启转发 | B 需要能对 8 网段做源地址转换，否则相机回包回不到 A | Windows 客户端 `New-NetNat` 依赖 Hyper-V/Server 版；改网关需动相机 | 不推荐 |
| C. B 上跑 SOCKS/HTTP 代理 | B 装代理，A 的软件走代理 | **必须改软件**（`cogsocket`/`images` 目前不支持代理） | 改代码 + 稳定性未知 | 不推荐 |
| D. 把 A 直接并入 20 网段 | 拉线或加网卡 | 物理条件、IP 规划冲突 | 与产线网络耦合 | 不可行（现场条件不允许） |

推荐方案 A 的核心优势：**B 只是「地址翻译器」，所有相机、PLC、产线网络配置零改动**；转发在内核态完成，15 台相机的流量开销可以忽略。

## 4. 方案 A 实施步骤

### 4.1 地址规划

| 项目 | 值 | 说明 |
|---|---|---|
| A 的互联网卡 | `192.168.8.1/24` | 静态 IP，与 B 同网段 |
| B 的互联网卡 | `192.168.8.2/24` | 静态 IP |
| 转发监听地址 | `192.168.8.2` | 必须是 B 上真实存在的地址 |
| 转发端口范围 | `20031–20198` | 对应 15 台相机 |

注意：A 上不要给 8 网段配默认网关（留空），避免抢占 `192.168.10.0/24` 与 `192.168.20.0/24` 之外的流量。

### 4.2 B 侧：启用端口转发

> 只需在 **B** 上执行；需要管理员权限。`portproxy` 仅支持 IPv4/TCP（本项目够用），规则重启后保留。

1）确认 IP Helper 服务在运行（portproxy 依赖它）：

```powershell
Get-Service iphlpsvc | Select-Object Status, StartType
# 若为 Stopped：
Set-Service iphlpsvc -StartupType Automatic
Start-Service iphlpsvc
```

2）批量添加转发规则（可直接复制执行）：

```powershell
# 相机末段 -> 相机 IP（15 台，按现场清单维护）
$cameras = @(31, 32, 198, 120, 121, 122, 123, 124, 125, 155, 156, 181, 182, 183, 184)
$listen  = "192.168.8.2"   # B 的互联网卡地址

foreach ($octet in $cameras) {
    $port = 20000 + $octet
    netsh interface portproxy add v4tov4 `
        listenaddress=$listen listenport=$port `
        connectaddress="192.168.20.$octet" connectport=80
}
netsh interface portproxy show v4tov4
```

3）放行防火墙（只允许 A 访问映射段，避免整段暴露）：

```powershell
New-NetFirewallRule -DisplayName "CameraTinyMES 相机转发" `
    -Direction Inbound -Action Allow -Protocol TCP `
    -LocalPort 20031-20198 -RemoteAddress 192.168.8.1
```

4）删除/重建（回滚时使用）：

```powershell
# 删除单条
netsh interface portproxy delete v4tov4 listenaddress=192.168.8.2 listenport=20031
# 全部清空
netsh interface portproxy reset
```

5）开机自检（可选，防止规则被清理软件删除）：

```powershell
# 保存为 check_portproxy.ps1，用计划任务「开机时」以 SYSTEM 运行
$expect = @(31,32,198,120,121,122,123,124,125,155,156,181,182,183,184)
$have = (netsh interface portproxy show v4tov4) -join "`n"
foreach ($octet in $expect) {
    $port = 20000 + $octet
    if ($have -notmatch "(?<!\d)$port(?!\d)") {
        netsh interface portproxy add v4tov4 listenaddress=192.168.8.2 `
            listenport=$port connectaddress="192.168.20.$octet" connectport=80
    }
}
```

### 4.3 A 侧：修改相机配置

本软件的相机配置在数据目录的 `config/cameras.json`（默认 `D:/JustSmart/CameraTinyMES/config/cameras.json`），是一个数组，每台相机一项：

```json
{
  "name": "OP40-31",
  "host": "192.168.8.2",
  "port": 20031,
  "username": "admin",
  "password": "******",
  "station": "OP40",
  "station_name": "焊缝检测",
  "model": "ISL38-33B"
}
```

改造原则：

| 字段 | 是否改动 | 说明 |
|---|---|---|
| `host` | 改为 `192.168.8.2` | B 的互联网卡地址 |
| `port` | 改为对应映射端口（20031 等） | 必须与 B 上的规则一致 |
| `name` / `station` / `station_name` / `model` | **不改** | 报表、OK/NG 统计仍按原工位归集 |
| `cells`（单元格配置） | **不改** | 与相机访问路径无关 |

也可以直接在软件的相机配置界面里把「地址」改成 `192.168.8.2`、「端口」改成 `20031`，效果相同。

### 4.4 软件侧无需改动

- 采集超时：图像 10s、点云 60s，同网段转发后延迟增加 < 1ms，无需调整。
- 断线重连：`reconnect_interval` 默认 5s，B 重启或网线抖动后可自动恢复。
- 若 B 上有安全软件会重置空闲连接，长连接会在几秒内自动重连，不影响取图。

## 6. 容量与性能评估

| 项目 | 估算 | 说明 |
|---|---|---|
| 长连接数 | 15 条 WebSocket 经 B | portproxy 为内核态转发，单机数千连接无压力 |
| 单次取图流量 | 约 60–150 KB | 640 宽 JPEG；原图 2448×2048 约 14 MB，软件已用 `?sz=` 缩放 |
| 典型带宽 | 15 台 × 1 次/5s × 100 KB ≈ **300 KB/s（约 2.4 Mbps）** | 百兆网段即可满足；千兆更宽松 |
| B 的 CPU | < 1% | 纯转发，无应用层解析 |
| 延迟增量 | < 1 ms | 同城/同机柜直连 |

若产线节拍更快（例如 1 秒/件），按 `台数 × (1/节拍) × 单帧大小` 重新核算；超过 60 Mbps 时建议把 8 网段改为千兆直连。

## 7. 安全建议

1. B 的防火墙只放行 `192.168.8.1` 访问 `20031–20198`，不要放行整个 8 网段。
2. 不要在 A 上加「192.168.20.0/24 的静态路由」，避免绕过转发规则直接暴露 20 网段。
3. 不要把 `192.168.20.x:80` 直接映射到 B 的对外网卡。
4. 相机口令建议与现场其他系统隔离，本软件配置文件 `cameras.json` 属敏感文件，注意目录权限。
5. B 上若有多块网卡，确认 8 网段网卡的「文件和打印机共享」按现场规范关闭。

## 8. 故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| `Test-NetConnection` 不通 | 规则未生效 / IP Helper 未启动 / 防火墙拦截 | `netsh interface portproxy show v4tov4` 核对；`Get-Service iphlpsvc` |
| 端口通但软件连不上 | 映射的相机 IP 写错，或相机 Web 服务未开 | 在 B 上 `curl http://192.168.20.31/` 直连验证 |
| 能取图但无图形/文字 | 会话断开导致图层 URL 404 | 正常现象，软件重连后自愈；持续出现检查 B 的 NAT 会话空闲超时 |
| 偶发「重连中」 | B 的网卡节能 / 网线质量 / 交换机端口 | 关闭网卡「允许计算机关闭此设备以节约电源」 |
| 图像加载慢 | 走了 `?sz=` 之外的原图路径 | 检查相机图层是否返回原始大图 |
| 某台相机完全不通 | B 上该相机网段未接线 / 相机掉电 | 在 B 上 ping 相机 IP |

## 9. 回滚方案

1. B：`netsh interface portproxy reset`，删除防火墙规则 `CameraTinyMES 相机转发`。
2. A：把 `cameras.json` 中 15 台相机的 `host`/`port` 改回原值（建议改造前先备份该文件）。
3. 本软件重启即回到改造前状态，A 侧 9 台相机不受影响。

## 附录 C：方案 B 的适用条件（备查）

若现场后续允许改动相机网关，可改为「A 加路由 + B 做 NAT」的纯三层方案：

- A：`route add 192.168.20.0 255.255.255.0 192.168.8.2 -p`
- B：开启 IP 转发，并对 `192.168.8.0/24 → 192.168.20.0/24` 做源地址转换
- 相机：默认网关指向 B 的 20 网段地址

该方案对相机侧有侵入（改网关），且 Windows 10/11 客户端的 NAT 依赖 Hyper-V 或 Server 版组件，现场维护成本高于端口转发，仅在「15 台以上、需要整段互访」时才有价值。
